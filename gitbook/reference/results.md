исправности; [`DETECTOR_FREEZE.md`](https://github.com/pmixay/ReSense/blob/main/docs/DETECTOR_FREEZE.md)).
Числа этой страницы сняты на печати 27.09 (независимая оценка 28.09). Шлюз обновления: 202 метрики
без изменений, две метрики синтетического набора F лучше; на поездке 5 из 11 271 кадров стали
`CAUTION` вместо `GO`, кадры `STOP` не менялись. Нода обновлена 29.09 (старт); умолчание
`catchup_startup_step` теперь 0, замеры старта ниже сняты с `0.2`.

**Как читать метки.** «Реальные» — записи организаторов; «синтетические» — объекты, вписанные
лучевым методом (ray casting) в реальные кадры. «В выборке» — на этих данных настраивались правила
детектора или обученная модель, так что это не независимая проверка. Настоящих препятствий, не
использованных при настройке, нет; разметка `doubleT_obstacle` сделана инструментами команды.

сливается с конструкцией у пути в `column`.

## Скорость <a href="#speed" id="speed"></a>

Цепочка жюри: команда образа по умолчанию → `ros2 bag play … --read-ahead-queue-size 10` от
имени uid 1000 → `/resense/*`. Сквозная задержка (e2e) — от публикации облака плеером (в оценке
28.09 — от его получения слушателем) до результата по этому облаку.

| что | результат | где |
|---|---|---|
| 360° (облака по 24 МБ), e2e p95 актуальных результатов | 85–94 мс с прогретым диском, 87–172 мс с холодным; на ВМ 81–82 и 88–96 мс | песочница 4 vCPU; ВМ |
| 360°, декодирование + обнаружение, p95 | 79–98 мс; на ВМ 63–72 мс | то же |
| 120°, e2e p95 | 49–78 мс | песочница |
| CPU, память ноды | 0,5–1,0 ядра; RSS 130–740 МБ | песочница |
| старт, обновление ноды 29.09 (с `catchup_startup_step:=0.2`; умолчание теперь 0 — не измерено): 360°, бэг в страничном кэше | медиана e2e за первые 3 с после первого облака 312–325 → **38–105 мс**; p95 по всем результатам 410–447 → 212–344 мс; первый `STOP` через 0,90–0,99 → 0,79–0,98 с после первого облака | A/B, песочница |
| то же, страничный кэш сброшен | первые 3 с: 829–1029 → **120–300 мс**; p95 по всем: 864–1084 → 333–599 мс; первый `STOP`: 1,16–1,35 → 0,81–1,16 с | A/B, песочница |

| декодирование облака | 360°: 20,3 → 16,6 мс (медиана), 120°: 7,4 → 4,8 мс; те же массивы байт в байт на всех 453 кадрах обеих исходных записей | песочница |
| прогрев | около 0,7 с при старте ноды; первый кадр 49 + 72 → около 31 + 42 мс (декодирование + обнаружение) | песочница |

Решения после старта обновление ноды не изменило (`STOP` на 55,5–56,6 м с 8-го кадра, `GO` на
111), установившееся время обработки — тоже. Без ядер на C++ (`RESENSE_NATIVE=0`) путь на numpy
на 360° облаках не укладывается в реальное время (p95 103 мс на ВМ). 8-ядерный стенд организаторов для
замеров был недоступен.

## Известные ограничения <a href="#limits" id="limits"></a>

* **Продолжение `STOP` по низкому объекту ограничено 0,3 с.** На 27.09 подтверждённый `STOP`
  пропадал на кадр, если объект не находили два кадра подряд: на `doubleT_obstacle` — `GO` на кадре
  111 и `CAUTION` на 117 и 197, пока предмет лежит на рельсе. С 29.09 `tracking.stop_keep_low_s` =
  0,3 с продолжает уже подтверждённый низкий `STOP` по возвратам, которым до порога высоты не хватает
  не более 0,03 м, и на этой записи пропусков нет. Правило подобрано на ней (в выборке); объект,
  теряющийся дольше 0,3 с, пропадёт, как раньше. Материалы:
  [`docs/evidence/frame111_2026-09-29/`](https://github.com/pmixay/ReSense/blob/main/docs/evidence/frame111_2026-09-29/README.md).
* **Дальность ограничена доверенной осью пути.** Дальше неё (коротко на платформах и двухпутных
  участках) объект на пути — `CAUTION`, а не `STOP`; рядом с конструкциями у пути он может
  слиться с ними.
* **Мелкие (0,3 м) и краевые объекты** подтверждаются только в пределах примерно 30–56 м.
* **Ложные `STOP` на платформах и стрелках**: 5 эпизодов на 83–148 м на одной записи
  (`squareT_platform_squareT_switch`), 2,3 эпизода на км на поездке.
* **`CAUTION` частый** (35–69 % кадров пустого тоннеля): это подсказка, поэтому пониженный до неё
  объект легко пропустить.
* **Обученная модель** может отложить сомнительный дальний `STOP` до 10 обработанных кадров;
  её положительные примеры синтетические, так что непохожий на них реальный объект может
  использовать всю задержку.
* **Всё в выборке**: правила настроены на тех же шести записях, поездке и наборе O, на которых
  измерены.
* **Скорость**: на 360° облаках и 4 vCPU p95 близок к периоду 100 мс, а с холодным диском
  превышает его; медленный диск тормозит плеер (360° бэг — около 4,5 ГБ за 20 с, нужно около 225 МБ/с).
* **Обязательные настройки жюри**: `--net=host` и `--read-ahead-queue-size 10`.
