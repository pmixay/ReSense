# Показ P2: короткий сценарий для капитана

> Подготовлено P2 для проверки на стенде. Реальный импорт Foxglove со второго устройства и две
> репетиции фиксируются капитаном отдельно; автоматический тест этого не заменяет.

## Перед выступлением

1. P1 передаёт проверенный образ `resense:latest`, путь к исходным bag-файлам и порядок
   запуска на стенде. При офлайн-передаче сначала загрузить образ по инструкции в основном
   README. В каталоге проекта задать `RESENSE_DATA=/путь/к/каталогу/с/bag` и
   `RESENSE_BAG=doubleT_obstacle`. Убедиться, что в каталоге есть сама запись.
2. На компьютере демонстрации запустить узел и мост:

   ```bash
   RESENSE_DATA=/путь/к/каталогу/с/bag docker compose --profile viz up detector foxglove
   ```

   RViz при наличии рабочего X11: `docker compose --profile viz up detector foxglove rviz`;
   для показа через Foxglove он не нужен.
3. В другом терминале после готовности узла запустить запись (ограниченный read-ahead обязателен):

   ```bash
   RESENSE_DATA=/путь/к/каталогу/с/bag RESENSE_BAG=doubleT_obstacle \
     docker compose --profile tools up player
   ```

   Чтобы увидеть текстовое решение без визуализации:
   `docker compose --profile tools run --rm echo`.

## Что показать за минуту

На **втором устройстве в той же сети**: Foxglove → Open connection → Foxglove WebSocket →
`ws://<адрес компьютера демонстрации>:8765` → Layout → Import from file →
`web/foxglove_layout.json`. Показать поступающее облако `/lidar_points` (или для другой записи
`/sensing/lidar/hesai128/pointcloud`), оранжевые точки коридора, красную рамку препятствия,
`/resense/decision` и численную дистанцию в `/resense/nearest_distance` и `/resense/status`.
Для `doubleT_obstacle` ожидается STOP около 56 м; это знакомая запись, не тест на новых данных.
Если облако перегружает сеть, отключить *только* сырой облачный слой в 3D: коридор и маркеры
оставить. Протокол моста проверяется командой
`python web/demo/check_foxglove_live.py --url ws://127.0.0.1:8765 --require-freshness`.

**Проверка потери связи:** прервать соединение второго устройства и восстановить его, убедиться
в поступлении новых статусов. Стандартный индикатор Foxglove показывает *последнее* полученное
значение (`LAST`) и не гасит его по таймеру: старое GO не называть текущим. Смотреть статус
соединения и свежесть `/resense/status`; при необходимости использовать веб-дашборд с
истечением актуальности. Не обещать, что в показе не будет отдельных пропусков детектора.

## Запасной показ и протокол проверки

Если живой показ недоступен: `docs/video/docker_chain_rviz.mp4` (архивная цепочка), затем
`docs/video/resense_overview.mp4` (текущие числовые карточки, старые иллюстративные клипы).
Не выдавать архивные клипы за запуск замороженного детектора на стенде. Для репетиции
записать коммит, ID образа, bag, адрес подключения, устройства, время, результат импорта,
STOP/дистанцию, проверку обрыва/восстановления, затраченное время и переход на запасной
показ. После первой репетиции исправить замечания, затем провести вторую целиком.

## Приватная презентация: передача данных

Капитан передаёт P2 **вне публичного репозитория** подтверждённые `captain`,
`captain_specialty`, `formed` (история формирования), `study`, `study_short`, `city`, а также
для каждого из четырёх участников `name`, `nick`, `photo` по образцу
`docs/presentation/team.example.json`. Файлы фото лежат рядом с `team.json` в игнорируемой
Git папке `docs/presentation/private/`; групповое фото `team_photo` необязательно.
P2 запускает `python scripts/build_deck.py --template /путь/к/шаблону.pptx --team
docs/presentation/private/team.json --out docs/presentation/private/ReSense_LCT2026.pptx`,
экспортирует PDF и проверяет слайды 2–4 визуально: имена, роли, фото, город, историю и отсутствие
незаполненных полей. В этом клоне подлинных персональных данных нет; проверка сборки на
вымышленных участниках не заменяет окончательную презентацию.

Окончательные сведения о команде, время питча и две репетиции — зона капитана и команды;
P2 участвует в сборке, показе и исправлении замечаний.
