## Демонстрация

Показ — с ноутбука капитана через демонстрацию экрана (питч онлайн). Та же цепочка, что у жюри в
[`README.md`](../README.md) «Кратко для жюри»; запись — знакомая `doubleT_obstacle`, это не тест на
новых данных.

**Заранее** (до выхода в эфир):

```bash
sudo sysctl -w net.core.rmem_max=33554432                # буфер UDP для 360° облаков
docker load -i resense-image-<версия>.tar.gz             # или: docker build -t resense -f docker/Dockerfile .
cat /data/for_hackathon/doubleT_obstacle/*.db3 > /dev/null   # запись — в кэш диска
xhost +local:docker
```

**На сцене:**

```bash
# консоль 1: узел + RViz; ждать строку «ReSense detector listening on» (~0,7 с прогрева)
docker run --rm -it --net=host --ipc=host -e DISPLAY -v /tmp/.X11-unix:/tmp/.X11-unix resense \
  ros2 launch resense_ros detector.launch.py rviz:=true freshness_mode:=replay
# консоль 2 (ROS 2 Humble на хосте): ограниченная очередь обязательна
ros2 bag play /data/for_hackathon/doubleT_obstacle --delay 3 --read-ahead-queue-size 10
# консоль 3 (по желанию): решение текстом
ros2 topic echo /resense/decision --field data
```

Без ROS 2 на хосте плеер — из образа: `RESENSE_DATA=/data/for_hackathon RESENSE_BAG=doubleT_obstacle
docker compose --profile tools up player`; всё одной командой — `scripts/play_bag.sh
/data/for_hackathon/doubleT_obstacle` (печатает «STOP 55.6 m» на каждую смену решения, без RViz).

**Что показать:** в RViz — облако, коридор габарита, красную рамку и STOP около 56 м в первые секунды
записи; затем человек уходит, STOP держится на предмете у рельса до конца записи. Дашборд (`web/index.html`)
в живом режиме нужен rosbridge на хосте (`ros2 launch rosbridge_server rosbridge_websocket_launch.xml`,
в образе его нет) → `ws://localhost:9090`; без него — скриншот дашборда на слайде 10. Удалённый
просмотр со второго устройства через Foxglove — [`web/DEMO_HANDOFF.md`](../web/DEMO_HANDOFF.md).

**Дополнительный путь — веб-прототип** (без ROS, Docker и X11; вне образа и релиза, PR #31;
[`webapp/README.md`](../webapp/README.md)). Заранее: `scripts/run_webapp.sh` (первый раз с интернетом —
`--install`) → http://localhost:8080, на «Загрузке» из «Папки на сервере» обработать `doubleT_obstacle` с
«Облаками точек» и открыть прогон в Плеере. Показать Прогон (решения по кадрам против разметки,
расстояние, оценка по разметке) и Плеер (облако из кабины, габарит 2,1 × 3,0 м, рамка и расстояние;
Space — пуск / пауза, `[` / `]` — события): после RViz, если остаётся время и капитан включит его в
план; запасной вариант ниже не меняется. Демо-запись — только как ход работы (она помечена «синтетическая»); числа речи — из
«Числа на слайдах и их источники». Скриншоты для слайдов — `webapp-*.jpg` в
[`images/`](images/README.md).

**Запасной вариант:** нет решения через ~30 с или упал X11 — не чинить в эфире, показать
[`video/docker_chain_rviz.mp4`](video/docker_chain_rviz.mp4) (69 с: узел и RViz в Docker, `ros2 bag

| ТЗ хочет 300 м, а у вас? | Лидар в этих тоннелях не даёт отражений дальше 209–210 м — ни в одном из 13 759 кадров. 300 м тут недостижимы для любого алгоритма. Наша дальность: человек (наша синтетика в реальной поездке) — **151** м, ящик организаторов — **98** м с первого появления. |
| Ложные тревоги на платформах? | Главный источник — платформы и стрелки. В поездке **27** событий за 13 км (**2,1** на км) — в выборке; вне выборки «мнение» давало 2,8 на км (детектор 27.09). До правил 29.09 было 32. |
| Всё настроено на тех же данных? | Да, правила и пороги подбирались на записях организаторов, и мы так и пишем «в выборке». Вне выборки: «мнение» на невиданных кусках поездки (2,8 на км), заранее заявленная проверка на новых местах (45 из 72 случаев, 0 срабатываний на контрольном фоне; детектор 27.09). Настоящая проверка — контрольный bag организаторов. |
| Мелкие объекты вдали? | Слабое место. Куб 0,3 м даёт 2–4 точки на 60–115 м; STOP для кубов организаторов — с **43–56** м. Ящик 0,5 м на полотне — в **2 из 6** подходов. |
| Правила других команд — это нормально? | Идеи из открытых репозиториев (TunnelGuard, Tactical-Inventor), код переписан у нас, авторство указано в ALGORITHM. 8 идей через полный гейт: 5 отклонили, 3 включили; `shell` выключили после своей проверки безопасности — висящий от свода кабель получал STOP с 21 м вместо 74 м. Остались «чистая серия» и запрет эго-движения. |
| Почему нет GPU? | Выигрыш — не больше 30–45 мс на кадр 360° против numpy, а контейнер с запросом GPU не стартует без nvidia-container-toolkit. На CPU p95 от кадра до решения — 81–82 мс при 360° (4 ядра, 28.09) плюс ~2 мс правил 29.09. |
| Скорость поезда не дают? | Не дают. Оцениваем свою скорость по лидару (медианная ошибка 0,07 м/с); она питает запрет эго-движения. С заданной скоростью человек подтверждался на 167 м (24.09) — это следующий шаг через одометрию. |
| Будет ли работать в других тоннелях? | Модель пути строится по рельсам и стенам без карты, крепление калибруется само. Реального человека, вставленного в 5 других тоннелей (независимая оценка 28.09, прежний детектор), устойчиво видели на 60 м в 11 из 15 окон, на 100 м — в 6 из 15. С запретом эго-движения этот тест для едущих окон некорректен. Нужна проверка на новых записях. |
| Почему так часто CAUTION? | CAUTION — подсказка, не тревога: объект у габарита снаружи, за доверенной дальностью, известная инфраструктура, сниженная исправность. Его много (49 % кадров пустых записей и 37 % поездки — оценка 28.09, прежний детектор); тормозит только STOP. |
| Кадр 111, GO на предмете? | Был у детектора 27.09: верх предмета на 4–7 мм ниже порога. Закрыт 29.09 удержанием подтверждённого низкого STOP на 0,3 с; подобрано на этой же записи — говорим прямо. Теперь STOP на **193 из 201** кадра без пропусков. |
| Какая задержка на стенде организаторов? | Стенд (i7-9700E) мы не измеряли. Замер с машиной: 81–82 мс p95 при 360° на ВМ с 4 физическими ядрами, 49–78 мс при 120°, 28.09. |
| Что если данные пропадут? | Нет свежего результата — FAULT или удержание STOP с последней дистанцией; потребитель проверяет `/resense/status` своим таймером. GO значит «препятствие не обнаружено», а не «путь свободен». |
