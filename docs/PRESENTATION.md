## Требования организаторов

* **Питч (ТЗ §8.8):** весит меньше техники; «за несколько минут»: **проблема → идея → алгоритм →
  демонстрация → результаты → что получилось**, затем главный кадр: «Вот поезд едет по тоннелю. Вот
  лидар. А вот препятствие, которое наш алгоритм увидел за X метров». Длительность не названа.
* **Демонстрация (ТЗ §4):** запустить контейнер → проиграть bag → показать облако → обнаружение →
  результат; цепочка «тоннель → облако → алгоритм → препятствие → расстояние». Показ в реальном
  времени приветствуется; удалённый показ допустим, но каждое решение организаторы запускают сами.
* **Видео (ТЗ §5, §7.2):** короткое видео работы алгоритма — обзорный ролик.
* **Шаблон:** https://docs.google.com/presentation/d/17ciElVAWgeuPLiFHw7y5HMaAXmTo7g16 (37 слайдов,

## Демонстрация

### Живая удалённая демонстрация (Foxglove со второго устройства)

Заранее на машине демонстрации: образ загружен (`docker load -i resense-image-<версия>.tar.gz` или
`docker build -t resense -f docker/Dockerfile .`), записи в `$RESENSE_DATA` (по умолчанию
`/data/for_hackathon`), `sudo sysctl -w net.core.rmem_max=33554432`, запись прочитана заранее
(`cat <бэг>/*.db3 > /dev/null`): на ВМ 28.09 задержка сетевого диска на 1,4 с сорвала прогон 120°, а
360° требует ~225 МБ/с. На втором устройстве в той же сети — Foxglove Studio (приложение или
https://app.foxglove.dev) с импортированным [`web/foxglove_layout.json`](../web/foxglove_layout.json).

```bash
RESENSE_BAG=doubleT_obstacle docker compose --profile viz up          # консоль 1: узел + мост Foxglove (+ RViz при X11)
RESENSE_BAG=doubleT_obstacle docker compose --profile tools up player # консоль 2: после строки узла «listening»
```

1. Второе устройство: **Open connection → Foxglove WebSocket → `ws://<адрес машины>:8765`**.
2. Показать цепочку ТЗ: сырое облако → точки коридора → рамки → `/resense/decision` и
   `/resense/nearest_distance`. Узел прогревается ~0,7 с до «listening» и догоняет стартовую пачку
   записи с шагом 0,2 с — первые секунды это нормально. На STOP — фраза главного кадра.
3. По медленной сети снять галочки сырых облаков (до 24 МБ на кадр 360°): коридор, рамки и графики
   идут на нескольких сотнях кБ/с. Индикаторы Foxglove показывают последнее полученное значение
   (`LAST`): при обрыве связи смотреть соединение и `/resense/status`.

Проверка связи и подробности — [`web/README.md`](../web/README.md) «Remote demo with Foxglove»; шаги
жюри без Compose — [`README.md`](../README.md) «Кратко для жюри».

## Вопросы жюри (ТЗ §8.7)

Подробно: [`DECISIONS.md`](DECISIONS.md), [`RESEARCH.md`](RESEARCH.md) §0, [журнал
экспериментов](archive/EXPERIMENTS_log_2026-09.md) §1 (эволюция), §4 (что не сработало), §9 (скорость).

* **Гипотезы.** Обученный 3D-детектор — отклонён: реальных положительных примеров нет. Сравнение с
  картой — нужны локализация и повторный проезд. Фоновая модель дальности на луч — отложена.
  **Выбрана** модель среды + габарит + кластеры + подтверждение: без классов, объяснима, на CPU. Своя
  скорость по лидару работает, но раннего STOP не даёт — опция.
* **Почему модель среды.** Вопрос «есть ли на пути то, чего там быть не должно», а не «что это»;
  габарит известен; стены видны дальше рельсов — ось продлевается по ним; геометрия переносится
  между проездами, внешний вид объектов — нет.
* **Компромиссы.** Подтверждение 0,5 с; низкий объект должен достать до плоскости головки рельса;
  вдали тревожат только высокие объекты; за зоной доверия оси — только предупреждение; CPU без GPU;
  нет семантики.
* **Трудные вопросы.** «GO в кадре 111?» — предмет пропущен два кадра подряд, удержание — один пропуск
  (`tracking.hold_misses`); детектор запечатан, ограничение названо. «Ложные тревоги?» — 2,8 на км на
  отложенных кусках; главный источник — платформы и стрелки (5 эпизодов на `squareT_platform_switch`).
  «Дальность?» — на 100 м устойчиво в 6 из 15 окон, пропуски — CAUTION. «А если `ros2 bag play` без
  флагов?» — результаты устаревшие; README и `scripts/play_bag.sh` задают `--read-ahead-queue-size 10`.
