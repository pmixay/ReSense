## Требования организаторов

* **Питч (ТЗ §8.8):** **проблема → идея → алгоритм → демонстрация → результаты → что получилось**; главный
  кадр: «Вот поезд едет по тоннелю. Вот лидар. А вот препятствие, которое наш алгоритм увидел за X метров».
  Длительность не подтверждена — готовим 5 минут.
* **Критерии экспертов (16.10,** [`FINALS_BRIEF_2026-10-16.md`](FINALS_BRIEF_2026-10-16.md)**):** 1 дальность
  детекции; 2 дальность габарита; 3 устойчивость габарита; 4 нет ложноположительных; 5 нет
  ложноотрицательных; 6 реальное время 10 Гц; 7 работа фильтра; 8 дополнительные функции; 9 удобство запуска.
  Отзыв о нашем проекте: **улучшить устойчивость габарита и синхронизацию габарита с поворотом**
  ([`organizers/answers.md`](organizers/answers.md) §10). Ложное срабатывание весит как пропуск; 300 м — идеал.
* **Демонстрация (ТЗ §4):** контейнер → bag → облако → обнаружение → расстояние; просьбы экспертов 16.10:
  Docker с графикой, RViz в контейнере, пауза и замедление бэгов из консоли, смена бэгов без перезапуска.
* **Видео (ТЗ §5, §7.2):** короткий ролик работы алгоритма — [`video/README.md`](video/README.md).
* **Шаблон** организаторов (37 слайдов, Montserrat): обязательный блок — слайды 7–11 шаблона (титульный; о команде; карточки
  участников; история команды; коротко о решении) — **без изменения дизайна и структуры, корректно заполненные**: название
  команды и задачи, ФИО и контактные данные всех участников, роли, суть и уникальность решения, план развития, сложности и
  вызовы (слайд 3 шаблона). Дальше — свои слайды на макетах 12–29; дизайн остальных слайдов можно менять.

## Демонстрация

Показ — с машины капитана через демонстрацию экрана (питч онлайн): RViz в контейнере и терминал рядом.
Версия — **1.2.0, образ релиза** (после публикации тега `v1.2.0`; до неё — сборка из `main` с печатью R3). Источник команд —
[`evidence/n1_n4_2026-10-18/HOWTO.md`](evidence/n1_n4_2026-10-18/HOWTO.md) и README «Новый Falcon и
интерактивный запуск». Обе записи — данные разработки, это не тест на новых данных.
[`web/DEMO_HANDOFF.md`](../web/DEMO_HANDOFF.md) описывает показ v1.0.0 (29.09); для 1.2.0 действует этот раздел.

**Заранее** (до эфира; на репетиции 1 — записать время каждого шага):

```bash
git checkout v1.2.0 && python3 scripts/detector_freeze.py verify    # PASS, 40 файлов (тег — после публикации релиза)
docker load -i resense-image-v1.2.0.tar.gz                           # архив релиза, интернет не нужен
sudo sysctl -w net.core.rmem_max=33554432                            # буфер UDP для 360° облаков
cat /data/for_hackathon/doubleT_obstacle/*.db3 > /dev/null            # Pandar-бэг — в кэш диска
cat /data/FALCON_DEMO_BAG/*.db3 > /dev/null                           # Falcon-бэг — в кэш диска
```

`xhost +` не нужен: `run_demo.sh` передаёт в контейнер сокет X11 и `XAUTHORITY` вызывающего.

**Falcon-бэг для показа (`FALCON_DEMO_BAG`) — собран 20.10** ([запись](evidence/falcon_demo_bag_2026-10-20/README.md)): кадры 2719–3150
записи (271,9–315,0 с), 432 сообщения, 43,1 с, 1,97 ГБ, sha256 db3 `b2c4a826…`; первый STOP — на 23,1 с воспроизведения, 127,18 м (холодный
старт узла). Файл лежит на Google Drive капитана, рядом с ним `bag/metadata.yaml` из записи; проверка после копирования —
`cd bag && sha256sum -c ../BAG_SHA256SUMS`. **Не проверено:** что `ros2 bag play` открывает этот бэг и что живой узел отвечает так же;
при `--rate 0,5` первый STOP — около 49 с от начала (дольше 30 с). **Не использовать** для показа первые 100 кадров записи
(`falcon_first100`): в них ложный STOP на конструкции в 115 м. Если к репетиции 2 (22.10) бэг не проверен — живой показ только
Pandar, Falcon — по слайду 14.

**На сцене** (одна консоль; второй бэг — в том же узле, без перезапуска контейнера):

```bash
IMAGE=resense:v1.2.0 scripts/run_demo.sh --rate 0.5 --clear-range-policy conservative \
  --sensor-profile pandar128 /data/for_hackathon/doubleT_obstacle \
  --sensor-profile falcon_ros /data/FALCON_DEMO_BAG
# программный OpenGL, если RViz не стартует:  LIBGL_ALWAYS_SOFTWARE=1 IMAGE=… scripts/run_demo.sh …
```

* `run_demo.sh` = `play_bag.sh --rviz --interactive`: узел и RViz в одном контейнере, плеер — в другом,
  в терминал печатается каждая смена решения («12.3 s  STOP  55.6 m  profile=pandar128»).
* Клавиши плеера: **пробел** — пауза и продолжение, **→** — один кадр на паузе, **↑ / ↓** — скорость.
* **Не нажимать Ctrl-C**: скрипт завершится и удалит узел. Узел живёт, пока играют все бэги.
* `--rate`: в HOWTO — 0,5 (проверено на машине с 1 CPU). Pandar-запись 360°; на 4 vCPU судья 13.10
  видел p95 111 мс, при 1,0 возможны устаревшие результаты (FAULT). На репетиции 1 выбрать 1,0, если
  после первого кадра нет FAULT, иначе 0,5. При 0,5 запись Pandar идёт 40 с, при 1,0 — 20 с: отсюда
  время показа (0:55 в речи рассчитано на 1,0).

**Что показать:** Pandar — коридор габарита, красная рамка и STOP около 56 м в первые секунды; пауза и
продолжение пробелом. Затем без перезапуска — Falcon: первая строка `profile=falcon_ros`, первый кадр —
FAULT/CAUTION (ориентация ещё не подтверждена; так и задумано), затем зелёный 3D-бокс габарита, CAUTION у
конструкций на 105,6 и 115 м, STOP по человеку. Решение и расстояние — в терминале.

**Если показ не идёт** (нет решения через ~30 с, упал X11 или RViz пуст): не чинить в эфире. Сказать:
«Живой показ сейчас не запустился — не буду тратить ваше время. Вот запись той же цепочки — архив 23

## Сборка колоды

Именная колода в репозитории правится **на месте**: шаблон и `team.json` для этого не нужны.

```bash
pip install python-pptx Pillow                                    # не в образе проекта
python scripts/build_deck.py --refresh docs/presentation/ReSense_LCT2026.pptx   # тексты, графики, заметки слайдов 4–16
python scripts/build_deck.py --audit docs/presentation/ReSense_LCT2026.pptx     # ≤80 слов на слайд, ≤1 100 всего
soffice --headless --convert-to pdf --outdir docs/presentation docs/presentation/ReSense_LCT2026.pptx  # нужны LibreOffice Impress и Montserrat
python -m pytest -q web/demo
python scripts/build_deck.py --check-gate docs/evidence/<гейт>/gate.json        # отличается ли GATE от другого гейта
```

`--refresh` вызывает те же функции слайдов, что и сборка из шаблона, но не трогает титульный слайд, слайды
команды (имена и фото), картинки, вырезанные при сборке, и размеры графиков; добавленные сборкой текстовые
поля находит по месту. Слайды, текст которых не менялся, выходят семантически теми же (проверено 19.10 на
слайдах 1–4, 6, 9); повторный `--refresh` ничего не меняет. После сборки просмотреть PDF глазами (слайды 5,
11, 12, 14 — самые плотные).

Сборка с нуля (шаблон организаторов из Google Slides; именная — с приватным `team.json` и фото вне git,
`docs/presentation/private/` в `.gitignore`, образец — [`presentation/team.example.json`](presentation/team.example.json)):

```bash
curl -L -o /tmp/template.pptx https://docs.google.com/presentation/d/17ciElVAWgeuPLiFHw7y5HMaAXmTo7g16/export/pptx
python scripts/build_deck.py --template /tmp/template.pptx --team docs/presentation/private/team.json \
    --out docs/presentation/ReSense_LCT2026.pptx
```

Без `--team` — публичная колода с ролями P1–P4. Любая сборка останавливается, если на слайде осталось поле
`<…>` или превышен бюджет слов.
