## Состав и роли

Организаторы рекомендуют пять ролей (README кейса): системный аналитик, инженер компьютерного
зрения, разработчик робототехники (ROS 2), специалист по работе с данными, разработчик ПО
(C++/Python). На четверых они распределены так (капитан — лид, второй участник — фронтенд):

| # | Участник | Роли по README организаторов | Зона ответственности | Ключевые артефакты |
|---|---|---|---|---|
| **P1** | **Капитан (лид)** | **Системный аналитик** + **Разработчик робототехники (ROS 2)** | требования ТЗ → архитектура и интерфейсы; ROS 2-нода, сообщения, launch, Docker; воспроизводимость «docker build → run → bag play»; протокол оценки; связь с организаторами и расширенный датасет; интеграция веток; финальная сборка и загрузка; лидирует питч | `docker/`, `ros2_ws/`, `README.md`, `docs/ARCHITECTURE.md`, чек-лист сдачи |
| **P2** | **Frontend / визуализация** | **Разработчик ПО** (Python/JS, инструменты и интерфейсы) | всё, что видит жюри: RViz-конфиг и Foxglove-layout, веб-дашборд (`web/`: облако + коридор + детекции + расстояние, журнал тревог), инструмент разметки кадров, видео работы, презентация (обязательные слайды 7–11 строго по шаблону), скриншоты в README | `web/`, `ros2_ws/.../rviz/`, видео, `docs/PRESENTATION.md`, pptx |

четверо, каждый в своей зоне; если понадобится C++ (производительность на стенде), это берёт P3.
Карта владения файлами — [`CAPTAIN.md`](CAPTAIN.md) §8.

## Правила

* Каждый PR — через ревью участника из другой зоны (в GitHub); `main` всегда собирается в Docker
  и проходит `pytest`; сливает капитан; красный `main` автор чинит за 1 ч или откатывает.
* Чужие файлы — только с согласия владельца.
* Заморозка: детектор и конфиг — **26.09, 20:00**, документация — **27.09, 20:00**, с 28.09 —
  только блокеры. Порог для изменения детектора и правила слияния — [`CAPTAIN.md`](CAPTAIN.md) §6.
* Числа живут в одном месте: [`EXPERIMENTS.md`](EXPERIMENTS.md) и сводка README; остальные
  документы ссылаются на них.

## Риски

* Ложные STOP на станциях и у торца платформы (25 из 27 эпизодов STOP на пустых бэгах) —
  главный риск для 8.1; работа P3 до заморозки 26.09.
* Дальность подтверждена только на синтетике (человек 148–154 м); на бэге организаторов объекты
  внутри габарита получают первый STOP не дальше 101 м, кубы 0,3 м — с 34–43 м.
* Объект на полотне между рельсами не сообщается (политика ниже габарита); вопрос Q3 организаторам.
* Время на кадр — 42–64 мс в среднем, p95 53–78 мс на 4 ядрах (23.09); стенд i7-9700E не
  измерен; накопление кадров может удвоить нагрузку.
* Стенд организаторов без GPU-зависимостей: не тащить CUDA в обязательные зависимости.
