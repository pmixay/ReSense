По указанию пользователя выполнение работ P4 этой сессией остановлено. Этот checkpoint
публикуется для самостоятельной работы P4. Дальнейшие задачи P1 (CI, PR/main и cleanup)

## 1. Откуда продолжать

Ветка: **`origin/integration/2026-10-15-16`**, а не текущий `main` и не старая P4-ветка.
Создать собственную ветку от опубликованного checkpoint, записать её полный стартовый SHA:

```bash
git fetch origin
git switch -c p4/eval-1.1.0-20261016 origin/integration/2026-10-15-16
git rev-parse HEAD
python scripts/release_meta.py version
python scripts/detector_freeze.py verify
```

Проверять печать в чистом **LF Linux checkout**. В Windows CRLF и сгенерированный `.pyd`
могут нарушить byte-seal; это не следует обходить изменением манифеста. Для работы на этом
компьютере использовать Docker/Linux и отдельный checkout, общий venv не переустанавливать.
Указать `PYTHONPATH` и `RESENSE_REPO`, проверить `resense.__file__`, native backend и версии.

## 3. Что P4 делать сейчас — по порядку

### A. Принять checkpoint и зафиксировать протокол

Прочитать эту передачу, [ledger](README.md), H4 selected и H5; проверить версию/печать,

несоответствии, а не вместо чтения существующих результатов.

### B. X3 — измерить новую базовую линию 1.1.0

Использовать существующий `scripts/robustness_battery.py` и
[протокол P4](../p4_start_2026-10-15/PROTOCOL.md), node-decoded float32 caches,
все четыре записи и все десять зарегистрированных вариантов, `-j 2`.
Точные аргументы брать из CLI `--help` и сохранённых команд первоначального X3.
Новый отчёт писать в отдельный каталог, старый baseline не заменять.

Сравнить с полной v1.0.0 baseline: не более +1 ложного эпизода на вариант и не более
2 потерянных совпадающих STOP-кадров на положительный объект/положительную запись
по зарегистрированному контракту. Проверять источники и способ matching; compact16 gate
и node-decoded X3 не являются взаимозаменяемыми. При переносе Windows → Linux установить
сопоставимость контрольного X3, не приписывать средовые различия детектору.

Результат: полный JSON, таблица по вариантам/объектам, source/input identities,
явные PASS/FAIL и причины, компактная таблица P2. Провал передать P1/P3 без подстройки детектора.

### C. X1 — атрибуция пропусков и позднего STOP

Выполнить карточку **X1** в [BACKLOG](../../BACKLOG.md): observation-only

без `unknown`; таблица причина → кадры по диапазонам дальности для P3.
Если контрольные числа карточки противоречат фактическому judge output, сохранить расхождение
и выяснить scorer/denominator; не менять результат ради ожидаемого числа.

проверку архива перед cleanup. Ни одна временная ветка/worktree пока не удалена.
