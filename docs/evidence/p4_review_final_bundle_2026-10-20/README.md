## 5. B2: should the captain accept the R3 STOPs at 37 m?

**Recommendation: accept.** P3's label (a thin vertical target held in the gauge at constant distance is an obstacle, so STOP is correct) is the better reading of what the organizers said, and the data give no
reason to prefer the veto.

* **What the code does** (reproduced, frame for frame): a 3 cm vertical target carried along at 15 m/s, speed given, 37 m ahead. R3 on: STOP from the 3rd frame (tall) / 2nd (hanging); R3 off: **no STOP at all**,
  a visible advisory from the 5th frame once the veto has its hits.
* **The label.** The organizers (relayed by the captain, 19.10, [`answers.md`](../../organizers/answers.md) §12): objects may move, even chaotically, and «всё, что попадает в габарит поезда — препятствие»; our
  consequence note there: an in-gauge object with CAUTION is a miss. A target that keeps its distance is not a static-world artefact; it is an object in the gauge, e.g. something moving on the line at train speed. Waiting for the
  veto means a CAUTION where the organizers expect a STOP.
* **The two costs are not symmetric in evidence.** *Exposure of the choice on real data:* the fast path is armed on 19 gate track-frames, changes 3 rows (all on the labelled hanging cable of Set O, true positives), 0 on the ride
  (P4's switch review of 20.10, not re-measured here); 0 on Falcon, 0 lost STOP in 29,765 X3 rows. No recording contains a cable-shaped target that rides with the train, so the false-alarm risk of accepting is **unmeasured, not measured high**. *The sensor geometry:* an artefact rigidly attached to
  the vehicle sits within a few metres of the sensor, not at 30–37 m; a ghost return would have to form ≥ 8 strict voxels, ≤ 0.15 m wide, ≥ 1.5 m tall, on 3 consecutive frames (≥ 0.3 s) to qualify.
* **What it does not cover:** general moving-target recall (M1 is open: a receding target at 80 m gets only 3 matched STOP frames); the wording comes through the captain's relay, not the organizers' text. If a cheap confirmation of
  «движется вместе с поездом — тоже препятствие» is possible (O1 is unanswered), ask; it does not change the recommendation.
* **What would change it:** a recording with a cable-shaped co-moving artefact at ≥ 30 m. None exists in the 15,269 gate rows (the 11,271-frame ride among them), the 4,443 Falcon rows or the 29,765 X3 rows.
* **Also seen (not a blocker):** the new fast path can start a STOP that a later frame interrupts. On the static control approached from 47 m, tall: STOP at frame 2 (44 m), none at 3, STOP from 4; hanging: STOP at 1, none at 2–6, STOP from 7.
  In frame 3 the cluster has **0 current points** (82 old points only), so R3 refuses to confirm on history; the base would show STOP only from frame 4 / 7, so no frame is worse than before. From `publish()` the node drops
  the STOP latch on a fresh valid frame without an obstacle, so the published decision would toggle; not tested end to end. One for P3 after the code stop; the jury answer is in `MOCK_JURY.md` N11.
