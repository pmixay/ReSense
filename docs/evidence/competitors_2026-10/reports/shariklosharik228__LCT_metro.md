# shariklosharik228/LCT_metro

## Verdict
Classical geometry, pure Python/numpy + sklearn DBSCAN (~3.3k LOC), plausible architecture (rails near, walls far, ego-motion accumulation, k-of-n tracker) but clearly the least mature of the three and behind ReSense on every axis. Claimed: 1 false frame in 1 611 frames of 5 organizer recordings, person found on `doubleT_obstacle` (47 frames, first at frame 16), sim person 100 % at 30-60 m and 56 % at 100 m. Trust: low. README itself says "no held-out validation, thresholds tuned on these same six recordings" and no obstacle is farther than 57 m in the data; latency 100-115 ms median on a cloud box (over the 100 ms budget); no result files saved.

## Pipeline
1. `detector.py:GeometricDetector.process`: lidar -> train frame, crop forward, keep every 2nd near point by scan order (<15 m), sort by x once.
2. Near axis (`rail_geometry.py:fit_rails`, `rail_heads.py:fit_heads`): trackbed plane + raised rail heads (histogram peaks 0.08-0.34 m, 4 cm cells, pair at 1.52 m) in 5 m slabs; `detector.py:stabilize` registers the previous path onto fresh observations.
3. Far axis (`wall_corridor.py:calibrate/extend/extrapolate`): rail-to-wall offsets calibrated while rails are visible (median, MAD < 0.15 m), then slab-by-slab walk along walls with constant-curvature prediction + innovation gate; slab grows 5 -> 20 m until it has >= 8 wall points; stops after 2 misses.
4. Learned normal cross-section: per 0.1 m lateral bin bed profile (`_update_bed_profile`), nearest continuous permanent structure per side/height band (`_update_free_space`, `_local_structure_limits`) clamps the clearance envelope (`effective_half`); far floor re-levelled per 5 m slab (`_correct_far_floor`).
5. ROI in track coordinates, 3-frame ego-motion accumulation (speed from wall-protrusion profile correlation, `ego_motion.py`), adaptive voxel + banded DBSCAN.
6. `detector.py:evaluate`: rules (long, flat, sparse, no fresh returns, far low/wide/overhead/boundary, attached to structure, corridor end, corridor unstable, boundary graze, extrapolated edge); `tracking.py`: 2/3 (<40 m), 3/5 (40-120 m), 4/6 (>120 m), jitter test, coasting 5 frames outside measured corridor. Output TTC and brake flag.

## Things done worse than ReSense / red flags
- Real recall is weak on the one positive recording: 47 detected frames of 201 (first at frame 16), vs 173 (KIWI7200) and 191 (hih0lp) alarm frames on the same recording; sim person 56 % at 100 m, nothing beyond.
- Hard visibility-style restrictions instead of evidence: beyond the rails only objects whose top reaches 0.8 m; low objects (< 0.5 m) only inside 35 m; no extrapolation of the corridor (`corridor_extrapolation = 0`). Result "1 false frame" is partly the price of a mostly blind far field.
- Latency: median 100-115 ms, p95 140-160 ms on 2 cores for the full cloud (README); sorting + sklearn DBSCAN per band; no C++. Misses our real-time bar.
- Envelope is 2.5 m wide at body height (config `clearance_width`), not 2.1 m, then clamped by learned structures; the gauge convention differs from the organizers' definition.
- Evaluation: 5 recordings (1 611 frames), no 20-min ride, no episodes per km, no hold-out ("thresholds were tuned on the same six recordings", README). Two README sentences mismatch the code history ("most parameters in the YAML were ignored by the algorithm before"), so earlier numbers are not comparable.

## Eval/data tooling worth borrowing
- `tools/bag_to_npz.py`: reads `.db3` with sqlite + numpy only (cm-quantised npz cache, 1 file per bag) - an easy dependency-free cache for CI; we already have our own cache, so low value.
- `src/metro_obstacle_core/simulation.py` (ray-cast tunnel with Hesai-128 beam grid, moving obstacles, dust) and `tools/benchmark_sim.py`: toy compared to our `resense/synthetic.py` + real-frame injection; not worth adopting.
