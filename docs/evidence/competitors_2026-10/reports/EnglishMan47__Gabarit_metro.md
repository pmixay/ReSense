# EnglishMan47/Gabarit_metro

## Verdict
Classical geometry, no learning; same family as ReSense (rails -> path -> corridor -> infrastructure rejection -> temporal confirmation), mature (CLI, web UI, ROS 2 node, tests, CI), ~45-70 ms/frame on 1 CPU core. Metrics in `docs/EXPERIMENTS.md` are reproducible by scripts but all are in-sample (rules were tuned 36 -> 4 false events on the same 5 empty bags, table "Как менялось качество"), and the range numbers come from a self-referential synthetic protocol (see red flags). Treat as a rich source of rules/ideas, not as evidence.

## Pipeline
1. `gabarit/cloud.py`: decode, dual-return handling (neighbouring columns = two echoes of one firing; keep one echo beyond 40 m, thin near field), ring recovery from elevation histogram peaks (`estimate_rings`), `dual_return_split` flag.
2. `track.py:TrackEstimator._calibrate`: mount (height/pitch/roll) from rail pairs (two peaks one gauge apart in a per-slice lateral max-height profile), EMA.
3. `track.py:estimate`: near field from rails; far field by 4 independent 3-state (value, slope, curvature) Kalman filters along range: left wall, right wall, floor, vault, each with a learned offset to the rail axis; wall-jump vs drift gating (`_fuse_walls`); then global robust penalised smoothing of c(s), z(s) on a 1 m grid (`_smooth_profile`), giving sigma_c(s), `observed_until`.
4. `egomotion.py`: BEV texture correlation + constant-velocity Kalman (ReSense has the same idea, `resense/egomotion.py`); previous path propagated and low-passed more when standing (`pipeline.py:_blend_path`).
5. `detect.py:track_coordinates/_detect_envelope`: points -> (s, d, h) track coords; corridor 2.2 x 3.0 m, h_min = 0.12 m + 2 sigma_z; 26-connected voxel clustering with range-growing voxel; ~15 rejection rules (sparse, ground, elongated, oblique, wall_attached, ceiling, column, longitudinal, fixture_row, line_far, wall_line, far_weak, pole_far, floating, high_far, edge_far); `detect_rail_objects` for bumps above rail head.
6. `tracker.py`: tracks in (s, d), 3-of-4 frames near, 6-of-8 beyond 60 m or for low objects, 4-frame hold; output free distance = `observed_until`, brake distance.

## Things done worse than ReSense / red flags
- Synthetic range protocol is self-referential: `scripts/synthetic_eval.py` places the object with the detector's own estimated path (`pipe.track.prev`: lateral d=0 is the estimated axis, base = estimated rail height), so axis error, the dominant real failure (our `beyond_axis`), cannot make it miss; the person is a perfect cylinder, fixed intensity 40, every ray that hits it returns (no dropout/reflectivity spread); success = confirmation within a 3+0.02 s tolerance of the injected s. "Person median 138 m, max 157 m, 14/14" is therefore not comparable with our 60/80/100/130 m stable-STOP rates for a real person; also only 14 runs, 5 empty bags.
- False-alarm evidence is thin: 4 events in 2287 frames (3.8 min), tuned by iteration on exactly these bags; the 20-min/13 km empty ride and its per-km rate are not used. Their 4 residual events are the same switch/platform stand-still we fail on, and they call it unsolved.
- Real obstacle: person found at frame 11 but the object on the rail only at frame 46 via a rule with `low_min_points=3`, bump >= 0.13 m, 6-of-8 hits, tuned on that single object; the 0.3 m box on rails is 8/24 found at median 26 m (ours 30-56 m).
- Organizer set (`docs/EXPERIMENTS.md` §4a): 5 false confirmations in 150 s, 3 of the 10 inserted objects missed, they argue it is the organizers' placement; rules that discard anything above 3.0 m or touching the edge are deliberate gates, as ours.
- Stricter-than-ours confirmation (3 of 4 frames, 0.3 s) is not safer: no cumulative STOP-episode count per km to compare.

## Eval/data tooling worth borrowing
- `scripts/eval_organizers.py:synthetic_mask`: ground truth for `cloud_with_fake_obj` = all points after the last (0,0,0) return in each cloud (organizers appended objects at the end). Cheap cross-check of our oracle matching by quantized XYZ.
- `scripts/synthetic_eval.py` run structure: object world-fixed at 200 m, closes at real ego speed, per-run `first_candidate_m`, `confirmed_at_m`, `hold_ratio`, `other_alarm_frames`, multiprocessing over bags x starts x shapes. Worth adopting the "first-confirm distance on approach + hold ratio" outputs, but placement must come from an independent reference (rails of a later frame / our `local_bed_z`), not the live model.
- `scripts/diag_events.py` event gallery and `scripts/audit_dataset.py` (SHA-256 inventory, duplicate detection) are minor.
- `gabarit/mlops.py` (MLflow registry of parameter sets) only if we want audit trail; not needed.
