# KirpaDmitriy/metroguard-lct2026

## Verdict
Hybrid: classical rail-pair geometry (fixed 2.1 m wide / 3.0 m high corridor, no curvature model, 150 m cap) plus a small learned "is this component an inserted box" ranker (logistic + 100 Extra Trees on 13 component summary features), plus a 2-of-3-frame evidence memory. Mature as engineering (77 logged experiments, Docker, ROS 2, web demo), weak as a detector. Its metrics come from synthetic boxes the ranker was trained on, plus normal bags whose labels are "empty because of the filename". The one real obstacle recording is not scored in any metric, and the default `memory_hybrid` gives 0 OBSTACLE frames on it (see red flags). Trust: low for recall, moderate for the negative results (tuning history is honest, many REJECT entries).

## Pipeline
1. `pointcloud2.py` / `fast_detector.py:cloud_arrays` read XYZI or XYZIRT. Axes: -y is forward, x is lateral. Crop to 3-150 m and |x| <= 4 m.
2. `fast_detector.py:_greedy_track_profile` finds the rail pair per 2 m range bin from a 5 cm (x,z) occupancy grid. It takes the best gauge-1.52 m pair with a center-continuity prior, then median-smooths and interpolates. `_continuity_track_profile` is an optional Viterbi variant.
3. `_surface_reference` computes the median height per 0.5 m x 0.1 m cell, with longitudinal leave-one-out neighbours. Candidate points are those >= 6 cm above that local surface inside |lat| <= 1.05 m and 3 m height.
4. `detect_obstacles.py:_cluster` voxelizes at 0.2 m and joins components. `_keep_supported_components` applies a range-adaptive minimum point count (6*(30/r)^0.35).
5. `risk_model.py` / `portable_trees.py` score each component (features: size, density, height, residual, lateral center, side clearance). The ranker is trained on ray-injected synthetic boxes (label 1) vs real components from 5 "normal" bags (label 0). Threshold = 99th percentile of the training bags' per-frame max score.
6. `evidence_memory.py:RangeEvidenceMemory` does range/lateral/height association. OBSTACLE needs 2 observations in 3 frames, with at least one over the threshold and the other >= 75 % of it.
7. `domain_guard.py` is a kNN "tunnel familiarity" check on outer-patch context descriptors (1960-sample bank). Unfamiliar context falls back to geometry (`runtime_detector.py:adapt_scores_to_tunnel_memory`).
8. Output CLEAR / OBSTACLE / UNKNOWN. UNKNOWN is used when rail observability is low or a candidate is not yet confirmed.

Techniques checked and already in ReSense: local per-cell surface residual (`lowobj.py:local_surface_mask`), range-normalised support (`sensor.py:expected_points`), occlusion-correct ray-cast injection (`synthetic.py:inject_obstacles`, which also removes the shadowed returns and adds dropout, so it is richer than theirs), real-object transplantation (`scripts/novel_placement_eval.py`), LiDAR-only ego-motion (`egomotion.py`, richer: static-background subtraction, two cues), exact fake-object labels (`scripts/label_fake_objects.py`, exact; theirs is an approximate 100 m-spacing forensic), axis-uncertainty margin (`gauge.reference_edge_margin`, with their EXP-063 changing no decision), UNKNOWN/FAULT with observability (`health.py`).

## Things done worse than ReSense / red flags
- The single real obstacle recording is scored nowhere. Its preset JSONs (`demo_app/presets/obstacle/*.json`) show the README default `memory_hybrid` and `tree_hybrid` give 0 OBSTACLE frames out of 201 (all UNKNOWN). The raw geometry flags 199/201 frames, from 18 m onwards, so it cannot localise anything. The README says "best" = memory_hybrid but never states that it misses the only real positive.
- The objects used to score recall are the ranker's own training distribution (axis-aligned boxes). EXP-057/058 show recall on unseen composite shapes collapses to 6.5 % (hybrid) and 14 % (joint shape+bag holdout). Their own audit says the ranker "recognizes generator shapes".
- Raw geometry alarms on 1842/2287 (80 %) of empty frames, with no curvature model, a fixed rectangular corridor, and no infrastructure downgrade logic. ReSense's empty-bag episode count (12 on the same 2287 frames) is no worse than their 15 episodes (22 alarm frames).
- Runtime: README admits p95 101.5 ms on their host. The preset logs show p95 104 ms and 7 fps throughput for the default mode, so it is not real time at 10 Hz on CPU.
- Official-synthetic "coverage" uses organizer order plus an assumed ~100 m spacing (pseudo-labels, flagged by the authors). The 1/7 official coverage of the default hybrid is also weak.
- Max range is 150 m by config, and EXP-069 found no effect from raising it: the usable range is the last reliable rail pair (median 89 m, best frame 184 m).

## Eval/data tooling worth borrowing
- `experiments/registry.json` format: each experiment records hypothesis, expected_effect, failure_condition (stated before the run), data.leakage_check, a `blind` flag and a decision (accept/reject). It is cheap to adopt in `docs/EXPERIMENTS.md`.
- Leave-one-recording-out harness with the alarm threshold set from training-fold normal frames only (`train_risk_model.py:calibrate_threshold`, `competition_scorecard.py`). Frame subsampling hid hard negatives in EXP-019, so they insist on full-sequence runs.
- `audit_synthetic_provenance.py` (EXP-062): the organizer synthetic bag is distinguishable by 16-byte XYZI vs 26-byte XYZIRT point layout and by long intensity==1 runs. They correctly refuse to use it as a runtime or label shortcut. ReSense already labels from the exact intensity==1 tail, so just keep it off the runtime path.
- OSDaR23 / OSDaR-AR adapters (`evaluate_osdar_transfer.py`, `convert_osdar_labels.py`) as a possible second domain for held-out recall, if the data can be fetched offline.
