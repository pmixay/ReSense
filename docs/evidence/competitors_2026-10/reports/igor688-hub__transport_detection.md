# igor688-hub/transport_detection

## Verdict
Classical geometry only, no learned detector: per-frame calibration, rail and wall axis fit, fixed 2.1 x 3.0 m gauge, range-banded clustering, multi-frame confirmation; Python + ROS 2 in Docker. Research-prototype maturity. Claims (0 false alarms on 5 empty bags, 2 false tracks on synthetic, real object at ~56 m) are in-sample: every rule was tuned on those same bags, with no held-out set and no FPR per km.

## Pipeline
1. `detector/pointcloud.py`: read PointCloud2, drop zero/NaN points (both 26 B and 16 B formats).
2. `detector/geometry.py:calibrate`: lowest point per 0.3 m cell, RANSAC plane with n_z >= 0.94 (floor, mount pitch/roll); `find_rails`: histogram pair search at 1.52 m gauge, then two polyfit passes -> rail centre, yaw, rail height.
3. `detector/path.py:estimate_path`: 5 m bins up to 230 m. Near (<30 m) rails give centre; far centre comes from wall offsets (10th pct of |d| in 0.8-2.6 m band, reference offsets 1.6-7 m) with distance-growing gate `0.6 + 0.005*s`. Huber-IRLS quadratic/cubic fit (`_fit`, delta 0.25). Staged extension over `path_stages` [45..230] with break when last wall support < stage - 25 m. Output: centre(s), floor(s), trusted `s_max`.
4. `detector/detect.py:gauge_mask`: 2.1 x 3.0 m corridor along fitted centre/floor, bottom 0.15 m, low band 0.85 m below 0.5 m, rail exclusion strip, +0.5 m margin for clustering.
5. `detect.py:cluster`: connected components in range bands (0.4/0.8/1.4 m radius) with along-range coordinate divided by 4 (`cluster_s_stretch`).
6. `detect.py:detect` + `accept`: per-cluster filters: distance-scaled min points, touch-penetration (>= 0.3 m deep), linear-structure rejection (length > 5 m, width < 0.5 m), span rejection (top > 2.4 m, or length > 4 m and top > 2.0 m), end guard (distance > 0.85 * s_max), far wall-support (off by default).
7. `detector/tracking.py:Tracker.update`: greedy nearest association (gate lateral 0.8 m, back 1.5 m, 25 m/s), confirm at 6 hits in window 8, consistency gate on history (lateral ptp <= 0.4, height ptp <= 0.6, step recede <= 2.0 m), hold 2 frames after miss.
8. `detector/pipeline.py:Pipeline.process`: warmup, returns GO/alarm + nearest distance; JSONL/ROS output.

## Things done worse than ReSense / red flags
- All thresholds were tuned on the same 5 empty recordings and the same 10 organiser objects; the 13 km empty ride is not used at all.
- Span and end-guard rules delete detections outright (`detect.py:accept`); ReSense's safety rule is downgrade-only.
- Synthetic matching is distance-only (`tools/eval_synthetic.py:evaluate`, tol 3 m + 4 %, lateral ignored), which is lenient.
- One real positive (56 m); the object vanishes after a few seconds and the README attributes that to the organisers removing it, which the data cannot show.
- Python only: 65-100 ms/frame on a laptop CPU; ROS replay drops 10-37 % of frames on the large-cloud bags (docs/experiments.md).

## Eval/data tooling worth borrowing
- Organizer synthetic GT from marker points: the injected points sit at the end of each frame after an empty-return delimiter with intensity == 1 (`tools/synthetic_gt.py:tail_points`). This gives per-frame object positions for evaluation only. Not present in ReSense (grep `tail|delimit|marker` in synthetic/cli/metrics: no match).
- Object linking across frames with a distance-consistent gate (`tools/eval_synthetic.py:link_gt`), reporting first-visible vs first-detected distance per object: a compact per-object table.
- Corridor-histogram waterfall (`analysis/corridor_waterfall.py`) for eyeballing range vs frame.
