# Tactical-Inventor/LCT-2026.NIIstovye

(Repo = single squashed commit b4a2658 "удалил лишнее", ~10k LOC Python + numba. Package `obstacle_detector/` + ROS2 wrapper `obstacle_detector_ros/`. Read-only analysis; nothing executed.)

## Verdict
Classical geometry + hand-written evidence tracker (no learning, no intensity, no calibration; assumes forward=-Y, up=+Z). Engineering maturity is high (determinism checks, ROS2/Docker tests), but evaluation maturity is zero in the repo: README and VALIDATION_ROS2.md give NO detection metrics (only a 150-frame parity run on synthetic `cloud_with_fake_obj`: 1 CLEAR / 81 CAUTION / 68 BLOCKED, first BLOCKED frame 82, "quality on the full dataset not claimed"). The many "measured on <recording>" numbers live only in code comments and cannot be re-checked: the eval scripts they cite (`route_eval/far_truth.py`, `beyond.py`, `test_spline_fast.py`) and all labels were deleted. Treat as a source of ideas, not of evidence.

Note: ReSense already took `far_rails` (resense/farrails.py, rejected by gate, DECISIONS #30) and `explained_run` from an earlier version of this repo, so those are not re-proposed here.

## Pipeline
1. `route/_core/*` (rail_pose_fast, rail_path_fast, tunnel_path_fast, wall_layers, distant_wall, single_bend/convex_bend, far_rails): per-frame rail-anchored single-bend spline route (lateral y(s), height z0(s)) fitted to near rails + outer tunnel-wall BEV bounds; envelope 2.1 x 3.0 m (`train_envelope.py`); selection with 0.7 m margin below rail heads (`route/_membership.py`).
2. `stabilization/*`: causal route filter: last 10 raw routes carried by ego-motion, median + rate limits solved as a small exact QP (`qp.py`, NNLS), one-sided curvature-sign prior (`one_sided_filter.py`), bend "preview" (`early_direction_filter.py`), recovery filter.
3. `tracking/ego_motion.py`: travel per frame from voxel overlap of previous vs current near cloud (3-40 m), locked tracking window, rail-curvature rotation.
4. `obstacles/detector.py`: per frame, return height above "its own cross-section at its own station" (`_surface.py`: surface = shape(offset)+drift(station)), rise > 0.10 m, grouping in route-local (station, offset, height) with range-growing lateral/height reach (`_groups.py`), then geometric sorting of each group into object / structure / track_furniture / unplaced / transient (flags: clipped by ceiling, edged, runs along, outside, sunken, level with rail heads, flat, piece of a line, past-rails uncertainty).
5. `tracking/obstacle_tracker.py`: evidence integrator per track (gain by confidence, range-dependent miss penalty, occlusion/blind-zone exemptions, confirm at evidence>=1.8 with >=2 object readings, release <0.6); structure/furniture never open a track.
6. `gauge/*`: only on tracks (no cloud search): classify observed shape vs gauge (>=3 distinct returns >=0.10 m deep, outer margin ramp 0-0.30 m over 30-50 m path), entry = 5 consecutive deep hits, exit = 5 consecutive outside, BLOCKED retained up to 20 frames on an ego-projected predicted shape. Output CLEAR/CAUTION/BLOCKED + distance.

## Things done worse than ReSense / red flags
- No metrics, no held-out or FPR-per-km numbers; eval/labels/scripts stripped; thresholds are overfit to named recordings in comments (roundT_*, squareT_*, new_data frame ranges). VALIDATION_ROS2.md validates plumbing only.
- Structure/track_furniture/unplaced groups never open a track (`obstacle_tracker.py:update`), and anything within 0.25 m of the 3.0 m ceiling is `structure` unless a >=0.6 m wide face is proven: hanging cable/pole/standing vehicle risk (same class of risk as our rejected `shell` rule). Our hanging/low-object stages are more careful.
- Hard-coded forward=-Y/up=+Z, no mount calibration, no intensity, ring only used for counting; frame-count (10 Hz) constants instead of seconds (their own note: timestamps jitter 53-140 ms while clouds advance evenly - worth checking against ReSense's `frame_dt` / 0.5 s rule).
- No per-frame timing or real-time claim (README: `rate_hz` "does not guarantee real time"); no far-range claim beyond the 56 m person/object on doubleT_obstacle; CLEAR means only "no active nominal objects in the available corridor".
- README status (CLEAR/CAUTION/BLOCKED) vs code (internal UNKNOWN mapped to CAUTION by the gauge layer): consistent at the output, but internal diagnostics differ.

## Eval/data tooling worth borrowing
- Auto truth for route-forecast error: compare the forecast route at frame t with the rails actually measured at frames t+k transported by ego-motion (the deleted `route_eval/far_truth.py`); gives a label-free axis-error-vs-distance curve to calibrate idea #1 on our 13 km ride.
- Self-truth for ego travel: a standing obstacle's range closure gives travel (`EgoMotion.correct`), usable to score our speed estimator.
- Determinism test pattern: bit-identical results across numba thread counts and file-vs-ROS adapter parity (`tests/check_recording.py`).
