# WWnotLL/ODSYWA3DL

## Verdict
Classical geometry (RANSAC ground plane + rail/bed axis + GOST "Om" gauge polygon + K-of-M confirmation), no learning. Pure-numpy core (~3.4k LOC) wrapped in a ROS 2 node with Docker; structurally close to ReSense but a strict subset in capability: effective checked range is only 21-26 m by rails, up to ~60 m where both tunnel walls are seen; person detected in 51 % of frames at 30 m, 24 % at 40 m, 10 % at 50 m (their README). Claimed metrics are in-sample, and the repo ships NO result files, logs or tests (the README links a `develop_ml` branch for tests; only `main` is cloned, no `tests/` dir), so none of the numbers can be checked.

## Pipeline
1. `preprocess.py`: drop invalid/zero points, dual-return collapse (`collapse_dual_returns` by ring+timestamp shot key; `collapse_by_direction`), ground plane by RANSAC with priority sampling from lateral outer strips, temporally tracked with a plane guard (`GroundTracker._check` vs rail-head heights), leveling into track frame.
2. `odometry.py`: per-frame advance from cross-correlation of longitudinal profiles (count/intensity/radius channels, detrended) of consecutive frames, 5-60 m.
3. `axis.py`: axis from two rival estimators (rail ridges, bed strip), trimmed to a clearance residual, cross-checked against each other; `AxisTracker` holds the axis when lost, propagated by odometry, sigma grows with hold path; `walls.py:extend_by_walls` extends the axis to <=60 m using both tunnel walls (per-height-bin wall offset table calibrated on the rail section).
4. `detector.py:detect`: corridor from Om polygon around the axis (cutouts for contact rail, conditional platform edge, rail-head mask), plus a 2.1 x 3.0 m train contour with penetration depth (`train_depth`, `depth_rank`=4th deepest point); voxel-grid connected components, point-count threshold falling with 1/range^2; confidence = margin / (2 sigma_edge).
5. `confirm.py`: odometry-compensated track gates, 3-of-5 confirmation; `AxisLossVerdict` (rule V2): if the axis is lost shortly after clusters were seen, latch STOP.
6. Output state 0 free / 1 not verified / 2 obstacle + `checked_range_m`.

## Things done worse than ReSense / red flags
- Claim mismatch: README says "0 false alarms on 1.78 km (2287 frames)"; docs/EXPERIMENTS.md still lists 27 alarm frames / 5 episodes = 1.3 per min on the same 2287 frames, and the 5 -> 0 step (train gauge) has no log, config evidence (`min_depth_m: 0.0`) or tests in the repo. Treat as unverified.
- Range is poor: 51/24/10 % person recall at 30/40/50 m; objects 0.24 x 0.25 m only detected 5-24 m; no result beyond 60 m. ReSense is at 60-100 m.
- Gauge floor 0.305 m above rail and no low-object stage: `A_min` 0.04 m^2 above floor, so 30 x 30 x 10 cm objects flat on rails are structurally invisible (they admit objects <0.15 m are not detected).
- Heavy sensor-specific assumptions (LIDAR_MOUNTS table, GOST Om polygon with platform cutout at 1450 mm +-45 mm); full RANSAC every 51st frame costs 200-570 ms spikes.
- Everything is in-sample on the same 6 recordings; the single obstacle recording (two persons in reflective vests, stationary train) is only used for the "intensity trap" remark.

## Eval/data tooling worth borrowing
- Injected-body protocol: insert synthetic bodies of several sizes on the axis in an empty recording and report recall per size/range (docs/EXPERIMENTS.md "Влияние размера объекта"), summarised as a minimum detectable area invariant. We already do the person variant; a size sweep (0.2-0.5 m cubes) at fixed ranges is a cheap addition.
- Per-recording train speeds listed in docs/EXPERIMENTS.md (doubleT_platform 18.8, roundT_doubleT 61.2, roundT_pressureGate_roundT 53.9, roundT_squareT_pressureGate_squareT 46.9, squareT_platform_squareT_switch 5.1 km/h, doubleT_obstacle 0): quick sanity check of `egomotion.py` (their provenance is unstated; verify against our `speed_reference.py` before use).
- Cold-start accounting (frames without axis after reset per recording): useful definition of "time to first valid verdict".
