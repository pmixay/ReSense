# kxsxlxv/MoscowMetropilot

## Verdict
Hybrid, leaning classical geometry: C++ core (~8.6k LOC, ROS-independent) plus a ROS 2 Humble node that publishes a single `std_msgs/Bool`. No learned model. Maturity: a clean, tested "precision-first" prototype (commit "Преза"). No metrics are in the repo: README says research materials and reports were excluded, and the only tests are synthetic smoke tests. Treat all performance claims as unverified.

## Pipeline
1. `pointcloud_decoder.cpp`: decode PointCloud2 (`/lidar_points`) and fixed challenge mount (`config/sensor_mount_challenge_assumed.yaml`, labelled "assumed", not calibrated).
2. `evidence.cpp:EvidenceBuilder::build`: identify laser firings by (timestamp, ring); collapse exact duplicate returns; count independent firings and acquisition groups.
3. `scene_projection.cpp` + `track_estimation.cpp:RailSupportExtractor`: per 2 m forward bin, lateral histogram of returns in a TOR-height band (-0.15..+0.12 m); pair peaks at 1.35-1.85 m separation; drift limit after baseline; sparse extension to 100 m.
4. `track_estimation.cpp:LocalTrackHypothesisSetExtractor`: primary track plus turnout branches admitted only when a paired-rail chain diverges from the primary path; quadratic lateral and linear vertical fit.
5. `swept_volume.cpp` + `sweep_geometry.cpp:place_planar_body`: articulated vehicle body placed along each branch path (bogie pivots, constant-radius throw, six component boxes from `config/vehicle_geometry.yaml`); nominal and uncertainty-expanded ("possible") sweeps.
6. `structural_residual.cpp:StructuralResidualEvaluator`: soft (never deleting) explanations: rail tube (0.07 m), low-track zone, longitudinal continuity over forward bins, side and shell continuity.
7. `candidate_grouping.cpp`: union-style grouping with range-dependent neighbour radius (clamp(0.03 + range*tan(0.15 deg), 0.05, 0.35) m; soft-structural endpoints not chained to each other). `current_scan_classifier.cpp`: "pure rail" and "broad low surface" (>=8 endpoints, >=1.5 m long, <=0.12 m vertical span) dispositions; supported vs tentative obstacles.
8. `precision_gate.cpp:PrecisionGate::update`: per-frame candidate must have >=12 independent firings, >=2 acquisition groups, >=6 nominal endpoints, >=50 % non-structural; centroid streak matched with speed-bounded slack (25 m/s); alarm at 3 consecutive frames; reset on gap >0.3 s, branch ambiguity, or invalid frame.
9. `ros2/metropilot_ros/src/obstacle_detector.cpp`: 100 ms timer; stale input (0.5 s) clears the flag; publishes Bool only.

## Things done worse than ReSense / red flags
- Output is `Bool` only (`obstacle_detector.cpp`, README). No distance, no GO/CAUTION/FAULT. The brief asks for distance ahead, so this does not meet the requirement. `false` is explicitly not free-path evidence (README).
- Calibration is "assumed" (`config/sensor_mount_challenge_assumed.yaml`, "NOT measured/calibrated"). ReSense auto-calibrates (`calibration.py`).
- Body width 2.83 m (`vehicle_geometry.yaml`) is wider than the task's 2.1 m gauge. Confirm what "inside sweep" means before borrowing idea 1.
- Gate thresholds (`min_firings=12`, `min_nominal_endpoints=6`, `confirmation_frames=3`) look tuned for near, dense targets. Range results are absent.
- Repo contains no measured results; the README says research and reports were excluded. Several README claims (precision-first, "conservative") have no numbers.

## Eval/data tooling worth borrowing
- `ros2/metropilot_ros/scripts/lidar_debug.py`: per-frame CSV with flag, round-trip latency and an `expected_scene` column. Simple labelling for replay.
- `cpp/tools/precision_replay.cpp` + `tools/test_precision_replay.py`: native SQLite/CDR replay with a synthetic tiny-bag fixture, no ROS needed.
- `tools/test_bag_sequence.py`: bag discovery order, metadata fallback, timestamp order, and read-only source checks.
- `cpp/tests/test_precision_gate.cpp`, `test_detector_pipeline.cpp`: unit tests on the gate state machine.
