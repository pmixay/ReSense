# garabot11/I.MOSCOW

## Verdict
Classical geometry, no learning (numpy+scipy, ~2.4k LOC detector, 38 unit tests, Docker+ROS2 node). Mature as a package, but the detector itself is a much simpler, narrower design than ReSense: one fixed box (half-width 1.0/1.4 m, bottom 0.3 m above rail, top 3.4 m), no low-object stage, no ego-motion, no accumulation, hard-coded sensor axes. Claimed 47/47 TP, 1 FP frame in 2488, precision 0.979: README itself admits this is tuned on the same 6 bags with ONE positive (stationary train, object at fixed 56 m, own manual labels, 154 "uncertain" frames excluded). Weak evidence, not comparable with our 13 km empty ride.

## Pipeline
1. `detector.py:process`: drop non-finite and exact-(0,0,0) returns (38-62 % of points), signed-permutation into (d, l, h) with configured `forward_axis`/`up_axis`, ROI.
2. `track_model.py:fit_rail_level`: per 2 m bin median of bed returns, two-stage robust quadratic (near bins first; far bins only inside a gate and with continuity), linear extrapolation beyond last observed bin.
3. `track_model.py:estimate_lateral_offset`: drainage-trough centre -> sensor lateral offset.
4. `track_model.py:estimate_track_curve`: axis l_c(d)=l0+a d+b d^2 from 4 cues: bed-profile mirror symmetry (near), free-space centres between walls (1.5-3 m band) and ceiling extent (3-5 m band) bin by bin, chained cross-correlation of lateral cross-section histograms between adjacent range bins, trough prior; joint robust LSQ with yaw/curvature priors.
5. Box follows axis; half-width shrinks with range and with curvature*d^2; margins grow beyond observed bed; top capped to observed ceiling - 0.6 m (`_ceiling_cap`).
6. Voxel dedupe (voxel grows with range) -> union-find clustering with range-growing radius -> rejection rules (see table) -> distance = 10th percentile of range.
7. `temporal.py`: greedy (d,l) association, 2-of-3 hits (3-of-4 beyond 100 m), reset on time gaps/backward jumps. Output CLEAR/DETECTED/UNKNOWN only (no GO/CAUTION/STOP).

Rules not worth taking (we have equal or better): range-dependent voxel/eps (`resense/clustering.py voxelize/_scaled`), exact-zero removal and duplicate collapse (`resense/pointcloud.py` dedup cache), far 3-of-4 confirmation (ours is stricter), single-ring far rule (our `far_min_ring_count` experiment exists, no gain), supported-range limit (our `beyond_axis`), time-gap reset.

## Things done worse than ReSense / red flags
- Box bottom is 0.3 m above rail (+ margins) and clusters need >=4-5 voxels: objects of 30x30x10 cm (task minimum) cannot be seen at all; no low-object stage. Their only positive is 0.85 m high.
- "Detection range" never measured: object fixed at 56 m, train stationary; README admits it. No FPR per km (4 min of data), no ego-motion/accumulation.
- Sensor frame is configured, not calibrated (`forward_axis: "-y"`, `up_axis`, trough/rail geometry of Moscow assumed); wrong mount = failure. ReSense auto-calibrates.
- Labels are self-made from projections and frame differencing; 286 of 2488 frames "uncertain" and excluded; thresholds tuned over `dev1..dev9` on the same bags (their own retrospective table shows precision 0.00 -> 1.00 from rule tuning on the evaluated frames).
- Single-frame decision, no object classes, no CAUTION level: infrastructure rules REJECT clusters outright (our rule: downgrade only), so they inherit exactly the safety risk we rejected for `shell`.
- Time 25-70 ms/frame single core but borderline on slow cores (4 E-cores, 921k pts: 84 ms node CPU per frame; decimation to 180k points drops recall to 12/47).

## Eval/data tooling worth borrowing
- `bag_tools.py:coverage` + `scripts/run_stream_test.sh`: independent sent/processed/published accounting by header stamp; found Humble `ros2 bag play` artefacts (use `--start-paused` + resume; `--wait-for-all-acked 5000` or last frame is lost). Check our ROS replay path for the same loss.
- Zero-copy raw CDR parser of PointCloud2 (`cloud_io.py`, equality checked on all 2488 messages): avoids rclpy conversion cost (107 -> 84 ms node CPU/frame on slow cores). Only relevant if our ROS node path is a bottleneck.
- Per-frame JSONL with every rejected cluster and its textual reason (`detector.py:FrameResult.to_dict`): cheap way to build a rule-level FP/recall table; ReSense likely logs similar, worth comparing format.
- Stationary-bag frame-difference labelling (`annotations/events.yaml`, `docs/data_notes.md`): trick for locating moving objects in recordings with a stopped train.
