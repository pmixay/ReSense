# W2nner/metro

## Verdict
Classical geometry with a range-image layer (pure NumPy/SciPy, no learned model, no map). Version 0.4.2 is the most complete app of the four: CLI, HTTP panel, ROS 2 node, SQLite journal, 41 unit tests, and Docker. The detector is very conservative: `reports/RELEASE_VALIDATION.md` gives 0 alarms on all platform/switch sets and on the `new_data` run (11271 frames, about 19 min at 10 Hz, probably the organizer's empty ride; not verified), but 11262 of those frames are UNCERTAIN (99.55 %). The numbers are on development data only ("Все данные использованы при разработке"), with no held-out set. Real-ray injection gives 15 m 8/9, 30 m 6/9, 100 m 0/9, and no returns beyond 150 m for the chosen rays (the report calls this a regression check, not range validation).

## Pipeline
1. `detector.py:Detector.process`: finite, non-zero points; optional `ring` (used only if <=256 unique values); axes X forward, Y left, Z up; range 1.5-320 m; self-masks.
2. `detector.py:estimate_floor`: densest lower surface per 3 m segment (4 cm histogram), robust plane fit.
3. `tunnel.py:profile, interpolate`: single-scan cross sections with 8 % growing along-track bins to 350 m; floor, roof, walls per section; floor capped at roof minus median tunnel height (3.4-6 m) from reliable 12-50 m sections.
4. `rails.py:track_model`: paired longitudinal ridges (`find_peaks`) give the centre and rail-head plane; `uncertainty()` per coordinate.
5. `trajectory.py:build_path`: near-rail anchor, then far walls followed only where their displacement is locally continuous; per-sample lateral and height uncertainty.
6. ROI: |y - centre| <= 1.05 m, 0.025 m < height < 3.0 m, inside the wall interval; "stable" if inside the uncertainty-shrunk band.
7. `detector.py` clusters: 26-connected voxels in three disjoint distance bands (0.16 / 0.28 / 0.45 m); rail-like filter (thin longitudinal, lateral residual 5-95 % < 0.16 m, height < 0.3 m) deletes.
8. Support per cluster: unique XYZ count >= threshold (6 near / 2 far), angular spread in both azimuth and elevation, and stable fraction >= 0.5.
9. `surfaces.py:foreground_edges` (depth-edge test per laser row) and `continuing_surfaces` (plane fit to surrounding returns); `range_context.py:check_context` (range-image components, coherence < 0.65 => unconfirmed).
10. Temporal: 2 hits in 3 frames, speed bound 23.6 m/s + 1 m, lateral 0.8 m, vertical 1 m; status OBSTACLE / UNCERTAIN / NO_OBSTACLE_DETECTED with explicit warnings.

## Things done worse than ReSense / red flags
- Output is so conservative that almost nothing gets a free-path status: 11262 of 11271 `new_data` frames are UNCERTAIN (`reports/release-linux-0.4.2/new_data.summary.json`). The report says UNCERTAIN is not free path. A zero-alarm rate with 99.5 % uncertainty is not usable for GO/CAUTION decisions.
- Hard deletions: `detector.py` rail-like filter (`suppressed += count; continue`) and `surfaces.py:continuing_surfaces` (`background=True`, removed from output). ReSense never deletes structure; these should be CAUTION downgrades.
- Frame-indexed regression fixes: `reports/RELEASE_VALIDATION.md` lists specific false-alarm frames (for example new_data 1230, 5490, 5563, ..., roundT_squareT 350) and "regressions for conflicting walls and wrong far rail pair". This tunes to known failures on the same data.
- Range is weak: real-ray injection 100 m 0/9 (returns in only 4 cases), 150-300 m no returns. The report itself says there is no real-world range validation and hidden tunnels are unchecked.
- Dead parameter: `trajectory.py:build_path(..., _alternative=False)`.

## Eval/data tooling worth borrowing
- `tools/inject_real_rays.py`: first-return ray/box insertion into real scans with occlusion; labels used only for scoring, never passed to `Detector.process`. We already have an equivalent (`synthetic.py:inject_obstacles`), so only the labelling discipline is new.
- `tools/audit_alarm_windows.py`: reprocess every baseline alarm and its +-3 neighbours with no history or UI labels, then review. Good for FP audits.
- `tools/evaluate_all.py` + `reports/release-linux-0.4.2/report.json`: SHA-256 of every detector and source file stored with the outputs, so each result is tied to a code version.
- `detector.py` `warnings` list (CALIBRATION_UNVERIFIED, SELF_MASK_NOT_CONFIGURED, PATH_ALIGNMENT_UNVERIFIED, SPARSE_OR_OCCLUDED_BEYOND_150M): explicit "what is unverified" flags in every result. Worth copying into our output.
