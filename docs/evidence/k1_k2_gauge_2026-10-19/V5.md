## 4. Set F: why v3 / v4 lost the far first detections (asked first)

v3 (`83c8894`) and v4 (`b2c523a` + v4 switches) have **identical** per-sequence first detections in all 30 sequences
(so the trusted-range policy, the only v3 / v4 difference, plays no part). Set F places each object on the evaluated
frame's **own axis** (`--placement-mode legacy`). On these straight splits the curvature step bends the joint axis at
150 m by 0.50 m (p50), 1.23 m (p90), 2.07 m (max) and makes it jump: the placed object's vehicle-frame Y changes frame
to frame by p90 0.24–0.49 m at 100–200 m (base 0.09–0.19 m). Example (trolley, split 140): at 195.9 m v3 places it at
Y −2.16 m, base at −1.18 m; no gauge candidate matches it in v3 until 162 m (base: from 196 m); first detection
194.0 → 110.5 m. Zeroing the step alone would not do: on straight track the joint curvature moves ±2e-4 with the step
anti-correlated (roundT_squareT frame 105: k +2.1e-4, step −8.3e-4), ±2.5 m at 150 m.
**v5a / v5b: all 30 first detections equal base**, placed-object jitter equal to base; rows differ only after the first
detection (near range) in 16–17 sequences. (`results/v5/setF_and_step.txt`.)

single recording, which reproduces the gate's rows exactly (0 of 345 / 252 / 545 frames differ: controls in
`results/v5/attribution.txt`).

* **doubleT_platform +1 episode (v5a, v5b): K1.** The new STOP (frames 40–41) is on base-shape frames
  (`joint_used` false). K1 alone (`walls_smoothing_distance` 1.5, nothing else): STOP frames 36–37, 40–41, 186–187,
  190–191 (4 episodes); v5a or v5b with K1 off: 36–37 only (= base). At 14–15 m/s K1 sets the EMA exponent to

* **roundT_doubleT +1 episode (v5a): the joint shape's step.** Frames 96–99, a person-sized cluster at 102 m, lateral
  0.3 m of the joint axis, `joint_used` true, step −1.4e-3. Against the driven path (ICP posesV, independent of the
  detector), at 102 m the joint axis is +1.31 m off (base +5.17 m: the base corridor is not on the track there at
  all); the cluster lies ~1.6 m from the path, outside the true gauge. v5b's cap ends the trusted range at 87 m in

* **set O background 5 frames (v5a): the joint shape.** Frames 661–665, an 8 m long structure at 116–123 m, lateral
  1.0–1.3 m, `joint_used` true (base k 2–3e-4, step −4.6 to −6.6e-4). Driven path at frame 661: base axis −0.28 m at

* **set O small_center −2 (all of v3, v4, v5a, v5b): the joint shape near range.** Frames 337–338 are joint frames

  frames later. The set O labels are measured from the shipped detector's axis (`_meta.axis`), so they cannot say

## 8. What was checked, how — and what was not

* **Pre-registration:** §9 committed before any v5 measurement. The two variants were not tuned afterwards; the
  threshold (1e-4) is the base straight-test limit, fixed a priori.
* **Off identity:** two independent checkers, every row and every frame, plus a positive control (§3).
* **Set F cause:** per-sequence rows of v3 / v4 / v5 against base (30 sequences), placed-object jitter, one raw
  sequence printed (§4).
* **Every failing row traced** to the shape actually used (`joint_used` recorded per frame, not reconstructed) and,
  where two switches could be responsible, separated by attribution runs whose harness reproduces the gate rows
  exactly (§6). Two rows checked against an independent truth (driven path from ICP poses).
* **Looked at the data:** frame rows of each new or lost STOP (distance, lateral, size, shape used), raw points and the
  driven path around the set O and roundT_doubleT alarms, the K1-2 probe rows (placement Y, candidate reasons).
* **Physical plausibility:** the axis errors (0.1–5 m at 55–120 m), train speeds (14–18 m/s), object sizes (person-sized
  cluster 0.58 × 0.66 × 1.54 m; 8 m lineside structure) are plausible; base's bent axis at 150 m on a straight platform
  (Y +2.2 m where the straight axis gives −0.95 m) is a known base error (REPORT top view).
* **Proxies are proxies:** K2-1 / B6-2 from the gate's per-frame track rows, through the registered scripts; controls:
  registered base track → 0.719 / 1.025 / 1.394 / 1.896 / 3.431 and 1.70 (exact); gate-row base → 0.65 / 0.97 / 1.38 /
  1.88 / 3.49 and 1.83; gate-row v3 → 0.40 / 0.45 / 0.43 / 0.36 / 0.45 and 0.48 vs registered v3 0.40 / 0.47 / 0.51 /
  0.52 / 0.56 and 0.50. The proxy underestimates K2-1 at ≥ 100 m by up to 0.16 m: it cannot decide the 0.5 m criterion.
* **Not measured, and why:** K2-1 / K2-2 / K2-3 / B6-1 / B6-3 by the registered method — the node-decoded caches of
  C (`roundT_pressureGate_roundT`) and B (`roundT_doubleT`) and the synthetic recordings are not in this container (the
  dataset zip was deleted; ~4 GB free disk, shared); F-1 — the Falcon source on Yandex Disk could not be reached from
  this session (permission denied); the ROS node / Docker path with the switches on; latency on an idle machine; the
  K2-only configuration (K1 off) as a whole. G3 untouched.
* **Checksums:** the folder's `SHA256SUMS` line of PROTOCOL.md now holds revision 4; V5.md, `results/v5/*` and
  `scripts/v5/*` were added. Five older lines name files that were never committed (`k2_1_base_cand3.jsonl`,
  `ride_episodes.jsonl`, three `.pyc`); left as found.
* **Incidents / corrections:** a `--set …=1e-4` is read by YAML as a string and the run fails at the first frame
  (TypeError) — caught in a development run, every measured run used `0.0001`. The base `setF_straight.json` of this
  container differs from the earlier container's off3 only in the last digits of the placed Y (1e-10 m); within this
  container off5 vs base is exactly equal.
