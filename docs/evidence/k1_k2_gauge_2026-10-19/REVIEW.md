## Switch-off identity (question 1)

Traced by reading every changed line against base: with `axis_joint_fit=false`, `walls_smoothing_distance=0`:
`bounds` is created under the same condition (`axis_wall_drift>0 or False`), `wall_drift` is computed under the same
condition (`bounds and axis_wall_drift>0` ≡ base `bounds`, since bounds is non-None only when drift>0); `joint` is
always None so the base branch runs unchanged; the split `if est is not None` keeps the base `else` branch attached;
`curv_step` stays exactly 0.0 (initialised from prior / default 0, only ever multiplied or set to 0) so `bent` is False
and every native-vs-numpy selection, `center_y`, `to_dict` (additive keys only when bent), `rotate_track_model`,
`estimate_rails` shapes and `wall_drift_range` are base; `kr = k`, `kw` unchanged; `bend = curvature`, `lim = 1e-4`;
`_travel` returns None before reading anything, `estimate_track(travel=None)` ignores it; `_ego_last` / `_travel_m`
are write-only state. `axis_straight` is a new dataclass field: not in `to_dict`, but it does enter `TrackModel.__eq__`
/ `dataclasses.asdict` (no such use found in resense/ or the ROS node). **No off-path difference found**; the
end-to-end check (Ran 3) agrees. Note the unit tests contain no full-pipeline off-vs-base test.

## Verdict

Off-identity holds (code reading of every changed path + the 300-frame spot check); the change is safe to merge
**with both switches off**. Turning it on is not safe as written: findings 1 and 2 together put a trusted corridor
metres off the track on a synthetic straight track with one short converging structure, and finding 7 can keep a
wrong axis for ~20 s at standstill. The identity criterion's script (C1) does not compare doubleT_platform at all.

**code: OK with fixes** (merge off only; ship-on blocked by findings 1, 2; 3–8 should be fixed before ON)
**criteria: issues** (C1 blocking; C2–C5 should-fix)
