## Interface and implementation

Node and launch defaults agree:

| Parameter | Default | Meaning |
|---|---:|---|
| `catchup_startup_step` | 0.2 s | Thin even short startup backlogs |
| `catchup_startup_max_lag` | 2.5 s | Startup recording-lag cutoff |
| `max_pending_frames` | 12 | Global Python pending-frame cap, across all inputs |
| `input_queue_depth` | 12 | DDS KEEP_LAST depth per subscription |
| `catchup_step` | 0.3 s | Later live catch-up step; 0 selects newest-only |
| `catchup_max_lag` | 5.0 s | Later live recording-lag cutoff |
| `decision_policy` | `v1` | Shared compatibility policy; v2 remains opt-in |
| `caution_distance_m` | 80.0 m | v2 margin-advisory distance limit, inclusive |
| `caution_compact_max_size_m` | 3.0 m | v2 compact box maximum extent, inclusive |

Startup pressure is measured decode + detect + publish wall time divided by the estimated
sensor period. Cost uses an EMA (latest frame weight 0.2; first observation initializes it).
At pressure ≥ 0.8, the startup step increases by one sensor period, capped at 0.3 s.
A nanosecond-sized comparison tolerance makes the exact 0.8 boundary stable. At 10 Hz and
90 ms/frame this selects 0.3 s. A single waiting frame is processed immediately.

Explicit every-frame compatibility is still available. For the old 20 s / 201-frame
experiment the tests set `catchup_startup_step=0`, `catchup_startup_max_lag=20.1`, and
`max_pending_frames=256`; setting the step alone does not bypass the memory/lag bounds.

Pruning now considers **every contiguous input epoch**, including inputs behind a different
head of queue. It runs on the callback's initial message, on each DDS take, and before
processing. After thinning, excess oldest frames are evicted to enforce the global cap.
Every eviction immediately increments both total drops and received/skipped drops.
Skip credits transfer to retained successors, preventing double-counting when a later header
gap is accounted. If a cap eviction has no same-input successor, one active-epoch counter
preserves its credit across ignored inputs. The counter is consumed at the next active frame's
accounting or cleared on a recording epoch change. Credits use retained-message counts plus
this single counter, replacing the old discarded-stamp list and its lossy truncation. Arrival
metadata and queued-epoch markers are keyed only by retained messages and removed when those
messages are processed or evicted.

Queued header epochs preserve their original boundary through thinning. In particular,
discarding the backwards first frame of a restarted bag cannot disguise that restart as an
ordinary forward gap. Continuity is checked before catch-up state is established, so even
a single-message new input starts its own epoch. Scene resets, mount restart rules, source
clock rejection, epoch progression, watchdog expiry, and STOP retention remain exercised by
the complete node suite.

Additional `status.node` telemetry:

- `pending_frames`: waiting frames, excluding the frame currently being processed;
- `max_pending_frames`: effective configured cap (at least one);
- `pending_overflow`: cumulative hard-cap evictions, a subset of received/skipped drops;
- `catchup_step_s`: effective catch-up step.

`catchup_skipped` now includes evictions before the first result and from abandoned queued
epochs. `dropped_frames` includes them immediately as well; a later inferred header gap adds
only missing frames not already counted. No skipped-record list is silently truncated.

### Shared C1 policy integration and one-period freshness allowance

The node constructs a validated, immutable `DecisionPolicy` from its three runtime parameters
at initialization. Node and launch defaults/types agree. `DetectorNode.decision(res,
policy='v1')` remains a static compatibility API delegating to the shared function. Publishing
calls `evaluate_decision(res, self.decision_policy)` **after** freshness health projection and
held-STOP projection. Markers use the same selected policy. Every status adds the selected
`decision_policy` version and sorted, deduplicated `caution_reason` array; the array is empty
on GO, STOP, FAULT, watchdog snapshots, and processing-error snapshots. Raw warning flags,
warning boxes, and their published topic remain present when opt-in v2 suppresses CAUTION.

Queue lag at most `input_period + 1e-6` seconds is now current even while `frame_in_catchup`
is true, but only after source clock, Python residence, maximum recording lag, epoch
progression and detector-health error checks pass. Both health `level` and `decision_level`
errors prevent a fresh-clear result from releasing a STOP latch. Lag above one input period
still gives catch-up CAUTION; lag above `max_result_age` still gives FAULT. The 0.2 s lag /
10 Hz CAUTION case remains covered. Bad clocks and held STOP retain priority.

**v1 remains the default.** As recorded in
[`caution_policy_2026-10-15/EVIDENCE.md`](../caution_policy_2026-10-15/EVIDENCE.md), the available
saved-output v2 rescore gave 30.46% empty CAUTION (target ≤25%) and lost 19 labelled in-gauge
object-frame alerts. This integration does not change the proposed v2 policy or its constants.
The shared [contract](../caution_policy_2026-10-15/CONTRACT.md) defines the additive reason codes.

### Independent-review corrections: raw validity and cross-input drop credits

The reviewer confirmed two integration defects in `1eed357`:

1. Malformed raw flags/health could leave freshness valid, expose a positive monitored range,
   clear a STOP latch, or be overwritten by catch-up health projection into CAUTION.
2. After active A stamp 0, A.1 evicted by twelve retained B frames, B ignored while A was
   live, and A resumed at .2, the node reported 2 dropped / 1 skipped instead of 1 / 1.

The node now validates obstacle, warning, and health independently using the shared **v1**
evaluation API before freshness evaluation, latch release, serialization, or health projection.
This is validity checking, not an advisory-policy decision: v2 suppression cannot validate a
malformed result, and raw STOP precedence cannot conceal invalid health or warning flags.
Actual Python/NumPy booleans retain their meaning; integers and strings remain invalid.
The node normalizes actual NumPy booleans before calling the shared API because NumPy 2
names its scalar type `bool`, while the shared pure module's compatibility check recognizes
the older `bool_` name. The raw detector result is not modified.

Invalid raw input gives invalid freshness (`detector_error` when the clocks/epoch pass), error
health, zero exposed clear/monitored ranges, `go_allowed: false`, and FAULT or a retained STOP.
A strict true raw obstacle still acquires/publishes STOP even with malformed health/warning,
with invalid monitoring and zero clear range. Only a genuinely valid later non-STOP result
releases the latch. All these remain ordinary frame snapshots, not accidental exceptions.

Cross-input cap eviction retains otherwise orphaned skip credits in `active_skip_credit`,
one integer for the currently active epoch. Prefix eviction means these credits precede its
next retained frame. They are added to that frame's successor credits for gap accounting,
then consumed, or cleared on any new recording. There is no per-topic/epoch history, skipped-
stamp list, retained cloud, or unbounded dictionary. Immediate eviction/drop counters and
the 12-frame/metadata cap are preserved. No ROS parameter, topic, launch default, one-period
tolerance, startup thinning value, or public status field changes in this correction.
