# Видео ReSense

> **Назначение:** что показывает обзорное видео, раскадровка и текст за кадром (для записи живого
> голоса), откуда каждое число, как пересобрать ролик и сценарий новой записи экрана, которую снимет
> команда.
> **Аудитория:** команда, жюри · **Ответственный:** капитан (P1) · **Язык:** RU
> **Проверено:** 2026-09-29 вечер, ролик собран `scripts/make_overview_video.py` на ветке
> `claude/admiring-pascal-ex9v51`; числа — **предварительные** (гейт `r_1e2ed82`, см. «Числа»)
> · **Статус:** текущий

ТЗ требует «короткое видео работы алгоритма» (§5, §7.2) и оценивает питч по цепочке «проблема → идея →
алгоритм → демонстрация → результаты → что получилось», которая заканчивается фразой «Вот поезд едет по
тоннелю. Вот лидар. А вот препятствие, которое наш алгоритм увидел за X метров» (§8.8). Обзорный ролик
построен ровно по этой цепочке.

## Что показывает ролик

1. **Проблема** — поезду без машиниста нужно самому понять, свободен ли путь; дальность по ТЗ; в
   данных почти нет препятствий, чтобы учить нейросеть.
2. **Идея** — описываем нормальный тоннель (ось пути по рельсам и стенам, габарит 2,1 × 3,0 м), а не
   объекты.
3. **Алгоритм** — пять шагов на кадр, выход GO / CAUTION / STOP / FAULT, задержка.
4. **Демонстрация** — цепочка жюри командами из README (`docker load` → `docker run` →
   `ros2 bag play` → `/resense/decision`), архивная запись этой цепочки с STOP в RViz, затем
   §8.8 на реальной записи: «Вот поезд в тоннеле. Вот лидар. А вот человек на пути: алгоритм увидел
   его за 56 метров» (поезд в этой записи стоит, поэтому «в тоннеле», а не «едет»).
5. **Результаты** — объекты организаторов (первый STOP по каждому), ложные тревоги на поездке и пяти
   пустых записях, правила 29.09 (два включены, одно выключено по итогам проверки безопасности),
   дальность на нашей синтетике.
6. **Что получилось** — узел ROS 2 в Docker без интернета и экран оператора; финал §8.8 дважды:
   реальный человек за 56 м (поезд стоит) и ящик 2 × 2 м организаторов за 98 м (поезд едет); карточка
   с цепочкой и ссылкой на код.

## Как пересобрать

```bash
pip install Pillow numpy imageio-ffmpeg piper-tts               # ffmpeg берётся из imageio-ffmpeg
python -m piper.download_voices ru_RU-ruslan-medium              # голос, ~63 МБ, huggingface.co/rhasspy/piper-voices
python scripts/make_overview_video.py --voice ru_RU-ruslan-medium.onnx   # ~4 мин: mp4 + srt в docs/video/
python scripts/make_overview_video.py                            # то же без голоса
python scripts/make_overview_video.py --check                    # проверить таблицу (тайминги, темп речи, источники)
python scripts/make_overview_video.py --frames 80,168 --frames-dir /tmp/f   # отдельные кадры PNG
python scripts/make_overview_video.py --voice ru_RU-ruslan-medium.onnx --voice-only   # только голос: влезает ли каждая реплика
python scripts/make_overview_video.py --script-md                # раскадровка и текст за кадром для этого README
python -m pytest -q tests/test_overview_video.py
```

С живым голосом: записать дорожку по разделу «Текст за кадром» (реплика в указанное время), затем
`ffmpeg -i docs/video/resense_overview.mp4 -i voice.wav -map 0:v -map 1:a -c:v copy -c:a aac -b:a 96k
-movflags +faststart out.mp4`.

## Голос

Сейчас в ролике **синтезированный** голос: Piper TTS (офлайн, нейросетевой), модель
`ru_RU-ruslan-medium`, текст — субтитры, где числа записаны словами (`spoken` в таблице), громкость
нормализована (−16 LUFS). Проверено только по длительностям и уровням, **на слух не проверено**:
возможны неверные ударения, особенно в латинских названиях (читаются как «докер лоуд», «рос два бэг
плэй», «гоу», «кошн», «фолт»). Перед отправкой ролик нужно прослушать; если голос режет слух — пересобрать
без `--voice` (немой ролик с субтитрами) или записать живой голос.

## Сценарий новой записи экрана (снимает команда)

Цель — заменить архивные клипы v0.6.2 записью текущего образа. Одна непрерывная запись экрана
1920 × 1080, ~2 мин, без монтажа внутри шагов; голос можно наложить потом по тексту выше.

**Подготовка** (не в кадре): образ текущего коммита; `sudo sysctl -w net.core.rmem_max=33554432`;
`cat /data/for_hackathon/doubleT_obstacle/*.db3 > /dev/null` (запись в кэш диска); `xhost +local:docker`.
Экран: слева RViz (2/3 ширины), справа три консоли друг под другом; шрифт консоли не меньше 16 пт,
чтобы команды читались в 1080p.

| # | время | в кадре | команда / действие | что должно быть видно |
|---|---|---|---|---|
| 1 | 0:00–0:10 | консоль 1 | `docker load -i resense-image-<версия>.tar.gz` (или `scripts/load_image.sh …` — проверка sha256 и запуска без сети) | `Loaded image: resense:…` |
| 2 | 0:10–0:25 | консоль 1 → RViz | `docker run --rm -it --net=host --ipc=host -e DISPLAY -v /tmp/.X11-unix:/tmp/.X11-unix resense ros2 launch resense_ros detector.launch.py rviz:=true freshness_mode:=replay` | строка «ReSense detector listening on», пустой RViz |
| 3 | 0:25–0:35 | консоль 3 | `ros2 topic echo /resense/decision --field data` | `FAULT` — входа ещё нет |
| 4 | 0:35–0:45 | консоль 2 | `ros2 bag play /data/for_hackathon/doubleT_obstacle --delay 3 --read-ahead-queue-size 10` | через ~3 с облако в RViz |
| 5 | 0:45–1:05 | RViz крупно, консоль 3 | ничего не трогать; в RViz вид «Driver's seat» | коридор габарита, красная рамка и «STOP … 56 m»; в консоли 3 поток `STOP` с первых секунд (кадр 8) — **момент §8.8: «Вот поезд в тоннеле. Вот лидар. А вот препятствие, которое наш алгоритм увидел за 56 метров»** |
| 6 | 1:05–1:20 | RViz, консоль 3 | ждать до конца записи (20 с) | человек уходит, STOP держится на предмете у рельса до конца, без GO |
| 7 | 1:20–1:30 | консоль 4 (по желанию) | `ros2 topic echo /resense/nearest_distance --field data` | ~56 |
| 8 | 1:30–2:00 | те же окна | повтор шага 4 с `/data/cloud_with_fake_obj` (набор O, распаковка — [`DATASET.md`](../DATASET.md); 7,4 ГБ, заранее прогреть кэш диска) | ящик 2 × 2 м в центре: STOP с первых секунд записи (первый STOP ~98 м, кадр 5), дистанция уменьшается — **«А вот поезд едет по тоннелю…»**; остальные объекты этой записи идут дальше, их можно не ждать |
| 9 | запас | браузер | `web/index.html`, «Запись» → статусы узла (или живой режим через rosbridge `ws://localhost:9090`) | экран оператора: баннер «ПРЕПЯТСТВИЕ 56 м», дальность контроля |

Одной командой вместо шагов 2–4: `scripts/play_bag.sh /data/for_hackathon/doubleT_obstacle` —
печатает каждую смену решения с расстоянием («12.3 s  STOP  55.6 m»), это тоже хороший кадр.
Узел в первые секунды догоняет стартовую пачку плеера — первые результаты могут быть FAULT/CAUTION,
это нормально (подробнее — [`web/DEMO_HANDOFF.md`](../../web/DEMO_HANDOFF.md)). Записать: дату, коммит и
ID образа, во сколько появился STOP и какая дистанция — в [`web/P2_STATUS.md`](../../web/P2_STATUS.md)
«Rehearsals».

После записи: положить клип в `docs/video/` (H.264, CRF 28–31, чтобы весил ≤ 10 МБ), заменить в
`BLOCKS` кадры `docker_chain_rviz.mp4` (58–76 с) и `doubleT_obstacle_cab.mp4` на новый клип с нужными
секундами `at=`, пересобрать ролик.

## Известные ограничения

* Клипы — архивные рендеры v0.6.2 и прежнего интерфейса (подписаны «архивная запись / архивное видео»);
  цепочка в RViz снята до 29.09 и заканчивается на CAUTION после конца записи — в ролик этот хвост не
  входит.
* В кадре веб-интерфейса (`dashboard_current.mp4`) мелким шрифтом виден архивный статус «latency p95
  106 ms over the 100 ms budget» — это другая машина и прежний детектор; число задержки ролика — из
  независимой оценки 28.09 (81–82 мс).
* Числа предварительные до финального прогона гейта (см. «Числа»); фраза «было 32, стало 26» измерена с
  тремя правилами, финальная — с двумя.
* Голос синтезированный и не прослушан человеком (см. «Голос»).
